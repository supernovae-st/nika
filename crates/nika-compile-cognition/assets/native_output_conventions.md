# Output conventions (the engine's own shapes; the request's words decide)
- `nika:read` in text mode returns one string, not an object with a `content` field. `nika:jq` receives exactly the value of `args.input`: parse JSON text with `input: "${{ with.text }}"` and `expression: "fromjson | ..."`. If you deliberately construct `input: {content: "${{ with.text }}"}`, select `.content | fromjson` first; `fromjson` on the wrapper itself fails. The `{records: ...}` convention is for already parsed records, not for parsing a read's text.
- Preserve literal path spelling, including spaces and every directory word, in constants, tool arguments and permits. `team notes/source.txt` and `notes/source.txt` name different files; do not shorten or translate a path. Quote multiword paths in YAML. If the unquoted extent is ambiguous, ask for the whole path rather than silently choosing its last word.
- Lines of a text file: every line ends with a newline. Read them with `split("\n") | map(rtrimstr("\r")) | if .[-1] == "" then .[:-1] else . end` (the empty segment after the final newline is the terminator, not a line); write them back with `if length > 0 then join("\n") + "\n" else "" end`, never `join("\n")` alone.
- A shape the request names is the shape written. « la liste des <champs> », « seulement <champ> », "the list of the <field>s", "only <field>": an array of those values (`map(.<field>)`), never objects that wrap them. « par <clé> », "per <key>", "by <key>": one object keyed by each value of that key (`group_by(.<key>) | map({key: (.[0].<key> | tostring), value: …}) | from_entries`), unless the request names another shape (records, a table, a list). For example « la liste des villes » is `["Lyon", "Nantes"]` and « le total par pays » is `{"FR": 12, "DE": 7}`.
- A total over every row is written as the engine's compute returns it. A total the engine types (a named total): to a structured file (json, csv, yaml, toml), the object with one field per named total (`{"total": 40}`); to a prose file (md, txt or any other destination), the value alone when it is the only total (`40`), while several totals keep the object. A computation the engine does not type is a jq program a seat synthesizes: the value that program returns, written as it is to a json or a prose file (`40` when it returns a number); to a csv, yaml or toml file it first passes through `nika:convert` from json, whose accepted input shapes apply. A shape the request names overrides both (« only the number » is the value alone; « an object with a total field » is that object). Over the one total the engine types, that value alone is stated as `alone: true` on its write: the typed computation stays under the engine's number law and a json file holds `40`. Several totals, or a csv, yaml or toml file, cannot hold one value alone and are refused; `alone` changes nothing for rows, a prose file or a seat's program. Add no other wrapper, key or field.
- When the request names no shape, keep the source's shape and the engine's shape of a total above: add no other wrapper, key or field, and state the shape you chose in `notes`.
- CSV header order is not JSON key order: `nika:convert {from: json, to: csv}` sorts keys unless `columns` supplies the order. When retaining a source header, set `columns` to that source’s ordered header from `observed_world` (including when the filtered array is empty). A filter keeps every source column unless the request changes the projection. For a projection, use the requested output columns in their requested order.
