# Nika 0.123 — Product Convergence

Status: accepted product direction for 0.123; implementation and qualification remain incomplete. This contract describes the target, not the behavior of released 0.122.

## Product and compiler

The user describes useful work, reviews an inspectable ordinary `.nika`, sees what was checked, rehearsed, observed and remains unknown, Saves without running, then separately authorizes a freshly admitted Run and receives Result + Proof. The normal production doctrine is **MODEL → SEMANTICS; NIKA → SOURCE**.

One compiler: intent → IntentContract → admitted Foundry knowledge → grounding and hard feasibility → semantic resolution → private SemanticPlan → deterministic Rust assembler → ordinary `.nika` → Parser/Check → supported confined Rehearsal → Behavioral Judge → READY/REPAIR/QUESTION/REFUSED/INCOMPLETE → Preview → exact-candidate consent → fresh admission → Run → Result + Proof.

IntentContract is the preserved satisfaction contract: goal, required work, inputs/outputs and their bindings, constraints/business rules, requested and forbidden effects, human gates, requested authority, postconditions, unknowns and provenance. SemanticPlan is a private proposed solution: operations, dependencies, bindings/provenance, capabilities, patterns, effects, gates, outputs, assumptions and unresolved decisions. Reuse existing Rust Plan/Sketch structures where sound; these conceptual names do not authorize a public DSL, file, SDK IR, compiler rewrite or renaming campaign.

Rust owns deterministic facts, types, graph/capability/policy constraints, hard feasibility, budgets, lowering, assembly, candidate identity, Check, consent binding, admission and runtime effect enforcement. Model output cannot grant authority or own final source bytes. Direct model→source may remain an isolated evaluation baseline, never a competing normal production path. Changing only the default to a less capable pilot does not satisfy convergence; creation, conversational revision, repair, CLI, Session, Serve and SDK must agree.

## Resolution and knowledge

HOT applies deterministic known reasoning. WARM resolves an honest finite remaining semantic ambiguity through DecisionSeat. COLD proposes semantics for genuinely open interpretation/composition/repair after recording why deterministic logic and bounded choice are insufficient. EXPLORE acquires permitted missing world/capability evidence or asks/abstains; it is a semantic strategy, not permission to invent facts or a demand to add a public enum immediately.

Foundry supplies admitted, versioned compiler knowledge by default where relevant: reusable patterns/blocks, capabilities/procedures, examples, counterexamples, repairs, known failures, relations, provenance and maturity. Retrieval supplies candidates, not truth, correctness or permission. The compiler revalidates feasibility. Measure FULL versus NO FOUNDRY with equal cases, model, DecisionSeat, budget and oracle; preserve harmful retrieval and zero/negative lift.

DecisionSeat is vendor-neutral bounded semantic judgment over a finite known admissible universe, with distributions and NONE/UNKNOWN where supported. Jev is a backend to qualify; Kev/local alternatives and Reflex remain evidence-gated. Hard filters precede selection; selected options are mechanically revalidated. No probability can override policy, resurrect impossible candidates or become consent. Elide calls when one candidate is proven admissible; record why calls occurred or were elided. Candidate hierarchy/top-K/independent qualification must measure coverage@K and wrong pruning. No forced fallback winner after all candidates fail independent qualification.

## Evidence, repair and authority

Rehearsal executes only supported copied, isolated or synthetic worlds. Protected real effects are never performed to obtain rehearsal evidence. Unsupported/NotRun/UNKNOWN remain visible. Discriminating worlds must reject plausible wrong work, not merely demonstrate that execution terminates.

The Behavioral Judge compares preserved intent obligations with observed behavior. Prefer exact assertions, typed comparisons, world/destination witnesses, then bounded semantic judgments, then an independent generative judge for open meaning. The proposing model cannot be the sole oracle. Mutation-test the oracle. Check green, successful execution, equality to reference source and a model's opinion are distinct observations.

Repair follows the same compiler, preserves the original obligations/policy/forbidden effects/authority and cumulative spend, retains all candidates and observations, then rechecks/rehearses/judges a new exact identity. Deleting a requirement is not a repair. Wrong READY is a P0 and gets a forensic receipt, never averaged away or relabeled success.

Save and Run have separate consent. Consent binds exact bytes/revision and cannot survive candidate or relevant admission-state changes. Fresh admission precedes real effects; a saved workflow, memory, Foundry record or earlier run supplies no renewed authority. Result reports usable outputs and uncertainty; Proof records observed evidence and its limits, not unobserved business truth.

## Atlas, Arena and learning

Atlas acquires permissible evidence of real automation demand with source/date/license/terms/provenance and semantic normalization. External workflows are witnesses of human needs, not unique implementation oracles. Arena owns independent contracts, discriminating worlds, mutations, protected semantic-seed splits, immutable attempts and accounting. Reuse existing implementations; no second benchmark platform.

Promotion: Atlas evidence → reusable candidate knowledge → development qualification → protected evaluation → measured downstream benefit → human review → Foundry promotion. Protected identities and all paraphrases/translations of a seed remain on one split side. Previously exposed sets are development evidence, never quietly restored to held-out status.

Reflex/CLM are research/data/evaluation seams, not shipped product claims. DecisionRecords bind engine/spec/context/question/candidate-set digests, knowledge refs, backend/output/abstention, downstream behavior, oracle provenance, split and observable cost/latency. Keep collection scoped and secrets out. Prefer exact behavioral labels over teacher preference. Compare simple baselines/Jev/Kev through relevant real harnesses before expensive training; shadow-only until lift survives independent qualification.

## Native workspace

Qualified bare `nika` enters the real fullscreen workspace. Recover existing native code before replacements. Project, conversation, persistent workflows, revision identity, visual task/dependency graph with drill-down, proposal, Check, rehearsal/UNKNOWN, authority/effects, Save, Run, live states/hierarchy, results/viewers, Proof and resume project canonical Session/runtime state. Do not create a TUI-only workflow model, permission model, fake run or second persistence owner. Inline/plain/accessibility remain usable explicit/fallback paths.

Actual-binary acceptance: bare → project → realistic unseen intent → needed question → visible compile/workflow/evidence/authority → conversational revision → Save → separate Run → live graph/results/Proof → exit/reopen/reuse without manual source repair. Prototype PTYs, galleries, screenshots and render units do not prove this journey. Resize, keyboard, ASCII/no-color, reduced motion and terminal restoration are included; SSH/tmux qualification is reported at its actual scope.

## Scope, change control and release

No V10, new public IR/language/compiler, SaaS/Control Plane/Connectome rewrite, template-count race or custom-model branding exercise. Before each new abstraction/field/API, the lane receipt answers the eight Socratic questions in the mandate: reproduced failure, reuse, smallest falsifiable implementation, kill criterion, independent oracle, responsible layer, ablation and user benefit.

One writer per shared contract. The integration owner controls architecture, integration and release claims. Each lane has pinned base, owned files, exclusions, dependencies, positive/negative acceptance and receipt. Final version sweep follows qualification, never program startup. Release publication follows repository authority. SHIPPED, MAIN, ROADMAP and RESEARCH/CONCEPT stay distinct on all active surfaces; historical evidence is preserved.
