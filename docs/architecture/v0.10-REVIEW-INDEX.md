## Cross-References

### How patterns relate to each other

```
ViewState Trait (isolation)
  ├─→ Enables independent testing of event coalescing
  ├─→ Allows DagPanel to be shared widget (used by multiple views)
  └─→ Simplifies provider modal (each provider is a view component)

Event Coalescing (performance)
  ├─→ Reduces pressure on memory bounds (fewer allocations)
  ├─→ Enables 60fps with DAG rendering
  └─→ Works with ring buffer (fewer events to coalesce = stable perf)

DAG Layout Caching (scalability)
  ├─→ Uses cached data from ring buffer (bounded event history)
  ├─→ Invoked from DagPanel (shared widget from ViewState views)
  └─→ Benefits from event coalescing (fewer invalidations)

Memory Bounds (stability)
  ├─→ Works with any pattern (universal improvement)
  ├─→ Ring buffer bounds event log
  ├─→ LRU bounds datastore
  └─→ Enables long-running workflows (1000+ tasks)

Provider Config Trait (maintainability)
  ├─→ Uses shared context from ViewState trait
  ├─→ Doesn't depend on other patterns
  └─→ Enables v0.11.0 release independent of Phase 0
```

| **DagLayout** | Cached DAG positions with invalidation | ARCHITECTURE-REVIEW 1.3 |
