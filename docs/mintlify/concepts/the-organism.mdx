Nika is a single Rust binary composed of ~40-42 crates (organs). Each organ has
one job. Together they form an engine that reads `.nika.yaml` workflows,
executes them across providers, and emits a stream of events you can audit.

Seven layers, strict downward dependencies only. No upward imports. Enforced
by `cargo-deny`.

## The verbs

Five. They do the actual work.

| Verb | What it does | Example |
|---|---|---|
| **`exec`** | Run a local shell command | `git clone`, `pytest`, `cargo build` |
| **`fetch`** | HTTP / URL / file / GitHub | Pull a README, call an API, download a file |
| **`invoke`** | Call a built-in tool or MCP tool | 63 built-ins, any MCP server |
| **`infer`** | Call an LLM provider | Anthropic, OpenAI, Google, Ollama, local GGUF |
| **`agent`** | Run a loop with tools (ReAct-style) | Multi-turn agent with memory |

Five verbs, closed set. Everything else is data.

Read [the verbs](/concepts/verbs) for the deep dive.

## The schema

Every `.nika.yaml` starts with `schema: nika/workflow@0.12`. That's the
contract. The schema is versioned, immutable per version, and published as
a JSON Schema at [nika.sh/schema/workflow.json](https://nika.sh/schema/workflow.json).

You can bump to a new schema version via `nika migrate`.

## The binding

Data flows between tasks via template expressions:

```yaml
tasks:
  - id: fetch_issue
    fetch:
      url: https://api.github.com/repos/supernovae-st/nika/issues/42

  - id: summarize
    depends_on: [fetch_issue]
    infer:
      provider: anthropic
      prompt: |
        Summarize this GitHub issue in one sentence:

        Title: {{ tasks.fetch_issue.output.title }}
        Body: {{ tasks.fetch_issue.output.body }}
```

`{{ tasks.X.output }}` is a binding. Nika resolves it at runtime with full
type awareness — including taint tracking (untrusted input → flagged).

## The events

Every verb emits a stream of events. You can follow them live:

```bash
nika run workflow.nika.yaml --events ndjson
```

```ndjson
{"ts":"T+00:00:00.00","kind":"workflow_start","workflow":"hello"}
{"ts":"T+00:00:00.05","kind":"task_start","task":"greet","verb":"infer"}
{"ts":"T+00:00:01.42","kind":"task_complete","task":"greet","status":"ok"}
{"ts":"T+00:00:01.42","kind":"workflow_complete","status":"ok"}
```

Every event has a schema. Consumers can pipe to `jq`, feed to an observability
system, or replay later.

## The providers

9 inference providers out of the box:

- **Cloud**: Anthropic, OpenAI, Google (Gemini), Mistral, Cohere, Groq, DeepSeek
- **Local**: Ollama (HTTP), native GGUF (mistral.rs)

All behind the same `infer:` verb. Switch provider = change one line.

## Growth model

The organism grows **one organ per admission**. Each admission requires all
[12 gates](https://nika.sh/method) to pass in the same commit. No exceptions.

You can watch the growth [live on the changelog](https://nika.sh/changelog).
