## Goal (v0.90 target)

Write a `.nika.yaml` file, run it, get structured output. No setup
beyond `nika` installed and one provider key.

## 1 — Make sure Nika sees a provider

```bash target — v0.90
nika doctor
```

If you see `no providers configured`, set a key:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
# or any of the 32 providers in the catalog
```

All provider env vars listed in [Providers catalog](/reference/providers-catalog).

## 2 — Write the workflow

Create `hello.nika.yaml`:

```yaml hello.nika.yaml
schema: nika/workflow@1
workflow: hello

tasks:
  - id: greet
    infer:
      provider: anthropic
      model: claude-sonnet-4-20250514
      messages:
        - role: user
          content: "Say hi to the chrysalis. Be brief."
```

Three things to notice:

- **`schema:`** declares the workflow-language version. `nika/workflow@1` is the locked v0.90 shape.
- **`workflow:`** is a human-readable name.
- **`tasks:`** is a list; each task has an `id` and one verb (here, `infer`).

## 3 — Run it

```bash target — v0.90
nika run hello.nika.yaml
```

Target output:

```
▶ greet  infer  → anthropic/claude-sonnet-4-20250514
  ┌─ output ──────────────────
  │ Welcome inside the chrysalis. 🦋
  └───────────────────────────
✓ greet  T+00:00:01.42  OK
```

## 4 — Add a second task that depends on the first

```yaml hello.nika.yaml
schema: nika/workflow@1
workflow: hello

tasks:
  - id: greet
    infer:
      provider: anthropic
      model: claude-sonnet-4-20250514
      messages:
        - role: user
          content: "Say hi to the chrysalis. Be brief."

  - id: critique
    depends_on: [greet]
    infer:
      provider: anthropic
      model: claude-sonnet-4-20250514
      messages:
        - role: user
          content: |
            The greeting was: {{ tasks.greet.output }}

            Rewrite it shorter and more enigmatic.
```

Notice `{{ tasks.greet.output }}` — that's a [binding](/concepts/bindings).
The engine injects the previous task's output into the prompt at runtime,
with explicit taint tracking and pipe filters.

## 5 — Get structured output

```yaml hello.nika.yaml
schema: nika/workflow@1
workflow: hello-structured

tasks:
  - id: names
    infer:
      provider: anthropic
      model: claude-sonnet-4-20250514
      messages:
        - role: user
          content: "Generate three names for a butterfly."
      response_format:
        type: json_schema
        json_schema:
          type: object
          properties:
            names:
              type: array
              items:
                type: string
                minLength: 3
                maxLength: 20
              minItems: 3
              maxItems: 3
          required: [names]
```

Nika takes the JSON Schema, asks the provider for output that conforms
(using each provider's native structured-output API where the [capability
rules](/reference/capabilities) allow it — schema mode, object mode, or
JSON-mode emulation), and validates the result against your schema before
passing it on.

```bash target — v0.90
nika run hello.nika.yaml
# Output is guaranteed to be { "names": ["...", "...", "..."] }
```

## What you just previewed

- Workflows are YAML files — `.nika.yaml`.
- Tasks are units of work, identified by `id`.
- Five verbs — `exec`, `fetch`, `invoke`, `infer`, `agent` — define what each task does.
- `depends_on:` builds a DAG.
- `{{ tasks.X.output }}` bindings flow data between tasks, with taint tracking.
- `response_format:` enforces JSON schemas on AI output.
