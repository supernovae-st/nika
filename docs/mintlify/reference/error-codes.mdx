Every error Nika emits carries a unique `NIKA-XXX` code. The canonical,
always-up-to-date list lives at
**[https://nika.sh/errors](https://nika.sh/errors)**.

Each code is addressable:

- `https://nika.sh/errors/NIKA-001/` — detail page
- `https://nika.sh/errors/catalog.json` — machine-readable catalog
- Every message printed by `nika` includes the code and a link

## Always fresh

This reference is generated from the `nika-error` crate at build time. The
numbers and wording may drift between dev logs — see
[nika.sh/errors](https://nika.sh/errors) for truth.

## Common codes

### NIKA-001 — Workflow parse error

The `.nika.yaml` file could not be parsed. Check YAML indentation, quoting,
and that top-level `schema:` and `tasks:` keys are present.

### NIKA-042 — Missing provider key

You wrote `provider: anthropic` but no `ANTHROPIC_API_KEY` is set. Run
`nika doctor` for full diagnosis, or `nika keys add anthropic` to save one
in your system keychain.

### NIKA-107 — Taint violation

A binding from an external source (fetch output, infer output, user input)
is being passed to a sensitive sink (exec command, HTTP URL) without an
explicit sanitization filter. Add `| shell_quote` or declare the task
`trusted: true` (if you know what you're doing).
