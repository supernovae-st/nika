# Nika v0.28 Workspace Restructure - Crate Boundary Design

**Date**: 2026-03-12
**Author**: Architecture Review
**Status**: Draft
**Version**: v0.28.0

---

## Executive Summary

This document defines the crate boundaries for restructuring Nika from a monolithic crate into a 4-crate workspace. The goal is to improve compilation times, enable better testing isolation, and allow downstream crates to depend on only what they need.

---

## Current State Analysis

### Monolithic Structure

```
tools/nika/ (single crate)
├── src/
│   ├── ast/           # YAML parsing, two-phase IR
│   ├── binding/       # Data flow, templates
│   ├── core/          # Provider/model/MCP definitions (zero-dep)
│   ├── dag/           # DAG structure, validation
│   ├── error.rs       # Error types
│   ├── event/         # Event sourcing
│   ├── io/            # Atomic writes, security
│   ├── mcp/           # MCP client (async, rmcp)
│   ├── provider/      # LLM providers (async, rig-core)
│   ├── runtime/       # Executor, agent loop (async)
│   ├── source/        # Span tracking
│   ├── store/         # RunContext (DashMap)
│   ├── tools/         # Builtin tools
│   ├── tui/           # Terminal UI (feature-gated)
│   └── util/          # Interner, JSONPath
├── Cargo.toml
└── 4,433 tests
```

### Pain Points

1. **Compilation Time**: Full rebuild on any change (~45s)
2. **Testing Isolation**: Tests for `ast/` pull in async runtime
3. **Feature Creep**: TUI depends on runtime concepts
4. **Circular Risk**: Runtime wants AST, AST validation wants runtime types

---

## Target Architecture

```
nika-workspace/
├── Cargo.toml              # [workspace] manifest
├── crates/
│   ├── nika-core/          # Types, AST, DAG (zero async)
│   ├── nika-runtime/       # Execution engine (async)
│   ├── nika-tui/           # Terminal UI (feature-gated)
│   └── nika/               # CLI binary
└── docs/
```

### Dependency Graph

```
                    ┌─────────────┐
                    │    nika     │ (CLI binary)
                    │   (v0.28)   │
                    └──────┬──────┘
                           │ depends on all
           ┌───────────────┼───────────────┐
           │               │               │
           ▼               ▼               ▼
    ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
    │  nika-tui   │ │nika-runtime│ │  (direct    │
    │   (v0.1)    │ │   (v0.1)   │ │   access)   │
    └──────┬──────┘ └──────┬──────┘ └─────────────┘
           │               │
           └───────┬───────┘
                   │ depends on
                   ▼
           ┌─────────────┐
           │  nika-core  │ (zero async)
           │   (v0.1)    │
           └─────────────┘
```

### Design Principles

1. **nika-core is sync-only**: No tokio, no async/await, no rmcp/rig-core
2. **nika-runtime owns async**: All async code lives here
3. **nika-tui owns rendering**: All ratatui/crossterm code here
4. **nika binary is thin**: CLI parsing + orchestration only

## Crate Definitions

### 1. nika-core (v0.1.0)

**Purpose**: Pure, synchronous types for workflow definition and validation.

**Philosophy**: This crate should compile in <5 seconds and have no async runtime.

#### Public API


### 4. nika (CLI binary, v0.28.0)

**Purpose**: CLI entry point and command orchestration.

**Philosophy**: Thin wrapper that delegates to runtime/tui.

#### Structure

```rust

use clap::{Parser, Subcommand};
use nika_core::{NikaError, Result};
use nika_runtime::Runner;
use nika_tui::{run_tui, run_tui_standalone};

    #[command(subcommand)]
    command: Option<Commands>,

    /// Workflow file to run (positional)
    workflow: Option<PathBuf>,
}

#[derive(Subcommand)]

    /// Run a workflow
    Run { workflow: PathBuf },
    /// Validate a workflow
    Check { workflow: PathBuf },
    /// Open Studio (YAML editor)
    Studio { workflow: Option<PathBuf> },
    /// Open Chat mode
    Chat {
        #[arg(long)]
        provider: Option<String>,
        #[arg(long)]
        model: Option<String>,

    // ... provider, model, mcp, sync, setup, daemon, jobs, backup
}
```

## Re-Export Strategy for Backward Compatibility

The main `nika` crate will re-export commonly used types to maintain API compatibility:

```rust
// nika/src/lib.rs (if building as library)

// Re-export from nika-core
pub use nika_core::{
    // AST
    Workflow, Task, TaskAction, Flow,
    InferParams, ExecParams, FetchParams, InvokeParams, AgentParams,
    OutputPolicy, OutputFormat,
    // DAG
    Dag, StableDag,
    // Event
    Event, EventKind, EventLog,
    // Store
    RunContext, TaskResult, TaskStatus,
    // Error
    NikaError, Result,
    // Source
    Span, Spanned, FileId,
};

// Re-export from nika-runtime
pub use nika_runtime::{
    Runner, TaskExecutor,
    McpClient, McpConfig,
    RigAgentLoop, RigProvider,
    EventEmitter, TraceWriter,
};

// Re-export from nika-tui (when feature enabled)
#[cfg(feature = "tui")]
pub use nika_tui::{
    run_tui, run_tui_standalone, run_tui_chat, run_tui_studio,
    App, TuiState, Theme,
};
```

## Circular Dependency Analysis

### Potential Risks

1. **AST validation wanting runtime types**
   - **Risk**: `ast::analyzer` might want `TaskStatus` enum
   - **Solution**: `TaskStatus` is in `nika-core::store`, not runtime

2. **Event types wanting MCP error codes**
   - **Risk**: `EventKind::McpError` contains `McpErrorCode`
   - **Solution**: Move `McpErrorCode` to `nika-core::error`

3. **Store wanting event types**
   - **Risk**: `TaskResult` might embed `Event`
   - **Solution**: `TaskResult` is pure data, events are separate

### Verified Safe Dependencies

```
nika-core (no runtime deps)
    ↓
nika-runtime (depends on nika-core)
    ↓
nika-tui (depends on both)
    ↓
nika (CLI, depends on all)
```

## Migration Strategy

### Phase 1: Extract nika-core (Week 1)

1. Create `crates/nika-core/` directory
2. Copy sync modules: source, error, ast, dag, binding, store, event (sync), core, io, util
3. Remove async dependencies
4. Add `pub use nika_core::*` to main crate temporarily
5. Run full test suite

### Phase 2: Extract nika-runtime (Week 2)

1. Create `crates/nika-runtime/` directory
2. Move async modules: runtime, mcp, provider, secrets, tools
3. Add `nika-core` dependency
4. Update imports throughout
5. Run full test suite

### Phase 3: Extract nika-tui (Week 3)

1. Create `crates/nika-tui/` directory
2. Move TUI modules: tui/, chat_agent
3. Add dependencies on core and runtime
4. Run TUI tests

### Phase 4: Slim CLI Binary (Week 4)

1. Move main.rs to `crates/nika/`
2. Add CLI command modules
3. Update re-exports for compatibility
4. Run integration tests
5. Update CI/CD
