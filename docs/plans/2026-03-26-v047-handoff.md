## PHASE 2: Complete Remaining 5 Items

### Task 1: M9 — DAG Panel Clone Elimination

**Problem**: `tools/nika-tui/src/views/chat/dag_panel.rs:35-40` clones all DagNodeData/DagEdgeData every frame via `node.clone()` / `edge.clone()`.

**Why it wasn't done**: ChatDagPanel owns mutable data — `update_node_state()` and `clear()` methods mutate the stored nodes. Changing to borrowed data (`&[DagNodeData]`) breaks these mutation methods.

**Recommended approach**: Keep ChatDagPanel owning data BUT cache it — build the panel ONCE when data changes (in `sync_dag_from_messages()`), store as a field on ChatView, and re-render from the cached panel each frame instead of rebuilding. This avoids 100+ clones/frame.

**Files to read**:
- `tools/nika-tui/src/views/chat/dag_panel.rs` (render_dag_panel)
- `tools/nika-tui/src/views/chat/widgets/dag_panel.rs` (ChatDagPanel struct, ~700 LOC)
- `tools/nika-tui/src/views/chat/mod.rs` (ChatView struct — dag_nodes, dag_edges fields)

**Verification**: `cargo test -p nika-tui --lib`

### Task 2: L4 — TransformExpr Pre-parsing (Optional, LOW ROI)

**Problem**: `tools/nika-engine/src/binding/template.rs` calls `TransformExpr::parse(&transform_str)` inside `resolve_with()` on every template variable. Same transform chains ("upper|trim") are re-parsed repeatedly.

**Why it wasn't done**: Requires either moving parsing to nika-core (arch refactor) or adding a global cache (complexity vs benefit unclear).
