## DAEMON DEEP DIVE

### Current Architecture

```
nika binary (CLIENT only)
    │
    ├── boot: load_from_daemon_or_fallback()
    │         │
    │         ├── [nika-daemon=on]  SpnClient → ~/.spn/daemon.sock → spn daemon → Keychain
    │         │                     (OnceLock singleton, 30s timeout, JSON/Unix socket)
    │         │
    │         └── [nika-daemon=off] env var → optional keyring (NIKA_KEYCHAIN_BOOT=1)
    │
    ├── provider set → NikaKeyring::set() → Keychain DIRECTLY (no daemon notify!)
    │
    └── nika job * → NOT IMPLEMENTED (protocol exists in spn-client)
```

### Key Files

| File | Role |
|------|------|
| `nika-engine/src/secrets/mod.rs` | Module router by feature flag |
| `nika-engine/src/secrets/daemon.rs` | IPC client (OnceLock<Mutex<Option<SpnClient>>>) |
| `nika-engine/src/secrets/fallback.rs` | Non-daemon: env + optional keyring |
| `nika-engine/src/secrets/keyring.rs` | NikaKeyring wrapper, keychain access |
| `nika-engine/src/secrets/result.rs` | SecretsLoadResult type |
| `nika-engine/src/runtime/boot.rs` | 7-phase boot, Phase 4 = secrets |
| `nika-engine/Cargo.toml:18` | `nika-daemon = ["dep:spn-client"]` |
| `nika/Cargo.toml` | `nika-daemon` NOT in default features |
| `spn-client 0.3.4` (external crate) | IPC client, protocol, paths |

### spn-client Protocol (IPC over Unix socket)

Wire format: 4-byte big-endian length + JSON payload.

**Secret commands (implemented in daemon.rs):**
- `GET_SECRET { provider }` → `SecretResult { value }`
- `HAS_SECRET { provider }` → `bool`

**Job commands (protocol exists, NOT wired in Nika):**
- `JOB_SUBMIT { workflow, args, name, priority }` → `JobSubmitted { job_id }`
- `JOB_STATUS { job_id }` → `JobStatusResult { state, ... }`
- `JOB_LIST { state_filter? }` → `JobListResult { jobs[] }`
- `JOB_CANCEL { job_id }` → `JobCancelled`
- `JOB_STATS` → `JobStatsResult { total, running, pending, has_nika }`

**Job states:** Pending → Running → Completed/Failed/Cancelled

### Known Bugs

1. **Stale cache**: `nika provider set anthropic` writes to keychain directly but never notifies daemon → daemon cache is stale until restart
2. **Socket path mismatch**: Contract tests document `~/.nika/daemon/nika.sock`, actual spn-client uses `~/.spn/daemon.sock`
3. **Feature not default**: `nika-daemon` is opt-in, so `cargo install nika` uses fallback path (env vars only)
4. **No lifecycle management**: Who starts the daemon? No launchd plist, no systemd unit, no auto-start

### Improvement Plan

**Phase 1 — Make daemon first-class:**
1. Enable `nika-daemon` in default features
2. Add `nika daemon status` (checks socket, PID, version)
3. Add daemon health check to `nika doctor`
4. Fix `provider set` to notify daemon via `REFRESH_SECRET` IPC

**Phase 2 — Job scheduler:**
1. Add `nika job submit workflow.nika.yaml` (uses JOB_SUBMIT IPC)

3. Add `nika job status <id>` (uses JOB_STATUS IPC)
4. Add `nika job cancel <id>` (uses JOB_CANCEL IPC)
5. TUI integration: job list panel in Control view

**Phase 3 — Watch & Events:**
1. `nika watch .` — file watcher + auto-rerun modified workflows
2. Daemon event bus: workflows emit events, TUI subscribes
3. LLM response cache in daemon (optional, for dev iteration speed)
