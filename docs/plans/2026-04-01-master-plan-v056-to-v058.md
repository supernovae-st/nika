## M3 — NIKA SERVE V2 (1-2 semaines)

> De subprocess à embedded Runner. Production-grade.

### Architecture

```
AVANT (v0.56 — subprocess) :
  POST /v1/run → spawn `nika run workflow.nika.yaml` → poll SQLite → GET /v1/status

APRÈS (v0.57 — embedded) :
  POST /v1/run → Runner::new(workflow).run() → EventLog → SSE stream
  GET /v1/events/{id} → SSE real-time events
  GET /v1/status/{id} → JSON status (toujours là pour compat)
```

### M3.1 — WorkflowExecutor trait

```rust
#[async_trait]
trait WorkflowExecutor: Send + Sync {
    async fn execute(&self, job: &Job) -> Result<JobResult, ExecutionError>;
    async fn cancel(&self, job_id: &str) -> Result<(), ExecutionError>;
}

struct SubprocessExecutor;   // V1 — garde pour fallback
struct EmbeddedExecutor;     // V2 — nouveau
```

### M3.2 — Embedded Runner

```
- Runner::new(workflow) directement dans le process serve
- Share provider connection pools (reqwest::Client)
- Per-workflow CancellationToken
- Capture EventLog en mémoire
```

### M3.3 — SSE Event Streaming

```
GET /v1/events/{id} → Server-Sent Events
- TaskStarted, TaskCompleted, TaskFailed
- InferStreamChunk (token par token)
- WorkflowCompleted
Format : data: {"event":"TaskCompleted","task_id":"step1","duration_ms":1234}\n\n
```

### M3.4 — Rate Limiting (tower-governor)

```
- GCRA algorithm (Generic Cell Rate Algorithm)
- Per-bearer-token limiting
- Config: max_concurrent, max_rpm dans config.toml
- Header: X-RateLimit-Remaining, X-RateLimit-Reset
```

### M3.5 — Observability

```
GET /metrics → Prometheus format
- nika_jobs_total{status="completed|failed|cancelled"}
- nika_jobs_active
- nika_job_duration_seconds (histogram)
- nika_tokens_total{provider="anthropic|openai|..."}
```

### M3.6 — Performance Stack

```toml
# Cargo.toml changes

### M3.7 — API Hardening

```
- Idempotency-Key header (prevent double execution)

### M5.1 — VaultEntry v2 Schema

```rust
// nika-core/src/vault.rs — extension du schema existant

#[derive(Serialize, Deserialize)]
enum VaultEntry {
    /// V1: simple API key (backward compat)
    Key(String),
    /// V2: multi-field credential
    Credentials {
        fields: HashMap<String, String>,
        service_url: Option<String>,
        expires_at: Option<DateTime<Utc>>,
        scopes: Vec<String>,
        category: CredentialCategory,
    },
}

#[derive(Serialize, Deserialize)]
enum CredentialCategory {
    LlmProvider,     // anthropic, openai, gemini, etc.
    SaasApi,         // github, linear, vercel, stripe
    Database,        // postgresql, redis, neo4j
    Communication,   // slack, telegram, email
    Cloud,           // scaleway, aws, gcp
    Social,          // twitter, youtube
    Certificate,     // ssh keys, tls certs
}
```

### M5.2 — Workflow binding : $vault.SERVICE.FIELD

```yaml
# AVANT (v0.55-v0.57) :
with:
  key: $env.STRIPE_SECRET_KEY

# APRÈS (v0.58) :
with:
  key: $vault.stripe.secret
  webhook: $vault.stripe.webhook

# Null safety :
with:
  key: $vault.stripe.secret ?? $env.STRIPE_SECRET_KEY
```

- Nouveau BindingSource::Vault dans nika-engine/src/binding/
