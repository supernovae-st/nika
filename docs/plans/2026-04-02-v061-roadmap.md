## v0.59.1 — Serve Hotfix (1 session)

> Priority: CRITICAL. These block Nicolas (nk-jungo) on production.

### BUG-1: Output polluted by CLI display
**File:** `nika-serve/src/config.rs`
**Problem:** Embedded executor inherits CLI display (stats, Gantt, summary). API responses contain ANSI + decorative output mixed with actual result.
**Fix:** Force `DetailLevel::Quiet` + `TestRenderer` when executor runs in embedded serve mode. No CLI decorations in API output.

### BUG-2: Env allowlist leaks NIKA_VAULT_PASSPHRASE
**File:** `nika-serve/src/worker.rs:288-297`
**Problem:** Env allowlist passes `NIKA_VAULT_PASSPHRASE` to spawned workflow processes. A malicious workflow with `exec: env` can read it.
**Fix:** Remove from allowlist. Daemon already has the passphrase — workflows don't need it.

### BUG-3: Shutdown signal arrives too late
**File:** `nika-serve/src/lib.rs:196-207`
**Problem:** `tokio::signal::ctrl_c()` only triggers after all requests drain. Workers don't get graceful shutdown.
**Fix:** Use `CancellationToken` shared with workers. On SIGINT/SIGTERM, cancel token fires immediately, workers get 5s grace period.

### Also fix:
- **M8:** Replace 9 `unsafe { set_var() }` call sites with `AtomicBool` / constructor injection
- **BUG-7:** `/metrics` endpoint must check auth token

### Commit plan (5 commits):
1. `fix(serve): force quiet renderer for embedded executor`
2. `fix(serve): remove NIKA_VAULT_PASSPHRASE from env allowlist`
3. `fix(serve): CancellationToken for graceful shutdown`
4. `fix(serve): auth check on /metrics endpoint`
5. `refactor(cli): replace unsafe set_var with AtomicBool`

| M1 | DNS rebinding: pin resolved IP at startup |

### Session 2: Artifact API

New endpoints:
```
GET  /api/v1/jobs/:id/artifacts          → list artifacts (name, size, type)
GET  /api/v1/jobs/:id/artifacts/:name    → download artifact (mmap, ETag, zero-copy)
```

- Read from `.nika/media/store/` CAS + `artifacts/` dir
- ETag based on blake3 hash (CAS) or mtime (regular files)
- Range requests for large files
- Content-Type detection via `infer` crate

### Session 3: Typed SSE + Checkpoints

**Typed SSE events:**
```json
{"type": "task_start", "task_id": "step1", "verb": "infer"}
{"type": "task_complete", "task_id": "step1", "duration_ms": 1200}
{"type": "artifact_written", "path": "report.md", "size": 4096}
{"type": "workflow_complete", "status": "success", "cost_usd": 0.12}
```

**Checkpoint store:**
- SQLite table: `checkpoints(job_id, task_id, output, created_at)`
- `nika run --resume <job_id>` — skip completed tasks
- `nika run --from <task_id>` — start from specific task

## v0.61.0 — Native SDKs (3-4 sessions)

> **Note:** `@supernovae-st/nika-client` (pure TypeScript HTTP client, zero deps) is DONE
> and published at `supernovae-studio/nika-client`. 56 tests, SSE streaming, polling, retry.
> This is the lightweight wrapper for Nicolas/nk-jungo. The native SDKs below are
> Rust-bound (napi-rs, PyO3) for embedded + remote use cases.

### Session 1: nika-sdk-core (Rust)

New crate: `tools/nika-sdk/`

```rust
use nika_sdk::{Client, RunOptions};

// Mode 1: Embedded (same process)
let client = Client::embedded()?;
let result = client.run("workflow.nika.yaml", RunOptions::default()).await?;

// Mode 2: Remote (HTTP to nika serve)
let client = Client::remote("http://localhost:3000", "token-xxx")?;
let job = client.submit("workflow.nika.yaml", inputs).await?;
let result = job.wait().await?;
```

- `Client::embedded()` — uses nika-engine Runner directly
- `Client::remote()` — HTTP client to nika serve API
- Streaming: `client.run_stream()` → `Stream<Item = Event>`
- Artifact access: `job.artifacts()` → `Vec<Artifact>`

### Session 2: @nika/sdk (Node.js via napi-rs)

New crate: `tools/nika-napi/`

```typescript
import { Client } from '@nika/sdk';

const client = Client.remote('http://localhost:3000', process.env.NIKA_TOKEN);
const job = await client.submit('workflow.nika.yaml', { topic: 'AI' });
const result = await job.wait();
console.log(result.output);
```

- napi-rs for zero-overhead Rust→Node bindings
- Publish to npm as `@nika/sdk`
- TypeScript types auto-generated from Rust structs

### Session 3: nika-py (Python via PyO3)

New crate: `tools/nika-py/`

```python
from nika import Client

client = Client.remote("http://localhost:3000", token="xxx")
job = client.submit("workflow.nika.yaml", inputs={"topic": "AI"})
result = job.wait()
print(result.output)
```

- PyO3 + maturin for build
- Publish to PyPI as `nika`
- Async support via `pyo3-asyncio` + `tokio`
