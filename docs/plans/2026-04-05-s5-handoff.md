## Part 2: runner.rs Split (3 commits)

### Current State

`runner.rs` is ~8,200 LOC with a monolithic `run()` method. The `Runner` struct has fields
set during init that are read during the DAG loop and finalize phases.

### Architecture

The `run()` method has 3 clear phases:

**Phase 1 — Init (~200 LOC)**
- Acquire lockfile (`.nika/workflow.lock`)
- Configure trace writer
- Resolve assets (providers, MCP, skills, context files)
- Initialize renderer (auto-select live vs classic)
- Emit WorkflowStarted event
- Set up global task semaphore

**Phase 2 — DAG Loop (~800 LOC)**
- Main `while !all_tasks_done` loop
- JoinSet for parallel task execution
- Task scheduling, dependency resolution
- Event collection and rendering
- Pause/resume handling
- Timeout enforcement

**Phase 3 — Finalize (~150 LOC)**
- Write artifact manifest
- Write execution trace
- Prune old traces
- Render summary
- Release lockfile

### Refactoring Plan

**Step 2.1 — Extract `init_run()`**

Move init code into `async fn init_run(&mut self) -> Result<(), NikaError>`.
This sets `self.resolved_assets`, `self.cli_renderer`, `self.trace_config`.
No return value needed — init modifies `&mut self`.

**Step 2.2 — Extract `finalize_run()`**

Move finalize code into `fn finalize_run(&mut self, total_duration_ms: u64) -> Result<Value, NikaError>`.
Takes the workflow result value and wraps it with summary + trace.

**Step 2.3 — Collapse `run()` to glue**

```rust
pub async fn run(&mut self) -> Result<Value, NikaError> {
    self.init_run().await?;
    let (result, duration_ms) = self.run_dag_loop().await?;
    self.finalize_run(duration_ms)?;
    Ok(result)
}
```

### Key Variables to Track

Init produces → DAG loop consumes:
- `resolved_assets` (already a struct field on Runner)
- `cli_renderer` (already a field)
- `trace_config` (already a field)
- `task_executor` (already a field)

DAG loop produces → Finalize consumes:
- `workflow_result: Value` (the output of the last task)
- `total_duration_ms: u64`
- `failed_task: Option<String>` (for error reporting)

Since these are all already fields on `Runner`, the split is purely structural — moving code blocks into methods with no signature changes.

Commits:
- `refactor(runner): extract init_run() — lockfile, assets, renderer init`
- `refactor(runner): extract finalize_run() — trace, summary, cleanup`
- `refactor(runner): collapse run() to init/loop/finalize glue`

## Part 3: Display Routing Fixes (2 commits)

### W6.2 — FetchExhausted/TaskRetry/ProviderAutoRetried through format_event

**Problem**: These 3 event types are emitted by the engine but bypass `format_event.rs`.
They go directly to the renderer with raw ANSI strings instead of using the shared
`fmt_*()` formatters.

**File**: `nika-engine/src/display/format_event.rs` (or `nika-display/src/format_event.rs` after extraction)

**Investigation needed**: Check if these events have `fmt_*()` functions already.
If not, add them. Then update `renderer.rs` and `live.rs` to call the shared formatters
instead of inlining format strings.

Search patterns:
```
grep -n "FetchExhausted\|TaskRetry\|ProviderAutoRetried" display/format_event.rs
grep -n "FetchExhausted\|TaskRetry\|ProviderAutoRetried" display/renderer.rs
grep -n "FetchExhausted\|TaskRetry\|ProviderAutoRetried" display/live.rs
```

Commit: `fix(display): route FetchExhausted/TaskRetry/ProviderAutoRetried through format_event`

### W6.3 — Classic renderer missing EventKind handlers

**Problem**: The classic renderer (CliRenderer in renderer.rs) handles fewer EventKind
variants than the live renderer (LiveRenderer in live.rs). Missing events are silently
dropped with a `_ =>` catch-all instead of being formatted.

**Investigation**: Compare the match arms in `CliRenderer::render()` (renderer.rs ~405)
vs `LiveRenderer` event handling (live.rs). List the EventKind variants present in
live.rs but missing from renderer.rs.

Common missing events:
- `RecordCompressed` / `RecordFailed`
- `SkillInjected`
- `AgentTurn` details
- `ArtifactWritten` details

Commit: `fix(display): classic renderer handles all EventKind variants`
