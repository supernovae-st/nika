## Part 3: LSP Diagnostics Handler (4-5 hours, ~3 commits)

### Problem

The LSP server has 12/13 handlers implemented, but NO `textDocument/publishDiagnostics`
handler. Parser error ranges from tree-sitter are computed but never converted to LSP
Diagnostic objects. Users see no error squiggles in VS Code / JetBrains.

### Gap Details

- Parser already produces `error_ranges: Vec<(usize, usize)>` with byte offsets
- These need to be converted to LSP `Diagnostic` with line/col positions
- The handler should fire on `textDocument/didOpen` and `textDocument/didChange`
- YAML bomb limit: enforce max file size before tree-sitter parse (DoS prevention)

### Files

```
tools/nika-lsp-core/src/handlers/        ← Add diagnostics.rs
tools/nika-lsp-core/src/handlers/mod.rs  ← Register handler
tools/nika-lsp/src/server.rs             ← Wire into server
```

### Steps

1. Add file size check (reject > 1MB YAML before parsing)
2. Create `handlers/diagnostics.rs` with `publish_diagnostics()` fn
3. Convert parser error_ranges to LSP Diagnostic
4. Wire into didOpen + didChange handlers
5. Add 10+ tests

Commits:
- `fix(lsp): add YAML bomb size limit (1MB)`
- `feat(lsp): publishDiagnostics handler`
- `test(lsp): diagnostics conversion + bomb limit`
