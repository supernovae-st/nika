## Phase 1: LSP publishDiagnostics Handler (4-5h, 3 commits)

### Context

The LSP server has 13 handlers (completion, hover, definition, etc.) but NO
`textDocument/publishDiagnostics` support. Parser error ranges from tree-sitter
ERROR nodes are computed in `recovery.rs` but never converted to LSP Diagnostics.
Users see no error squiggles in VS Code/JetBrains for broken `.nika.yaml` files.

### Architecture

```
nika-lsp-core/src/                     (protocol-agnostic intelligence)
├── parse/recovery.rs                   ← tree-sitter ERROR node detection
├── analysis/context.rs                 ← AnalysisContext with document state
├── handlers/diagnostics.rs             ← NEW: compute Diagnostic objects
└── handler.rs                          ← NikaHandler trait

nika-lsp/src/server.rs                 (tower-lsp protocol adapter)
└── did_open / did_change              ← Wire diagnostic computation + publish
```

**Key principle**: nika-lsp-core is protocol-agnostic. It returns its own types
(byte offsets, severity enums). nika-lsp converts those to tower-lsp/LSP types.

### Commit 1: YAML Bomb Size Limit

Enforce max file size before tree-sitter parse (DoS prevention).

**`nika-lsp-core/src/analysis/context.rs`** — add constant and early return:
```rust
/// Maximum YAML file size for LSP analysis (1 MiB).
/// Prevents DoS from massive files that tree-sitter would try to parse.
const MAX_YAML_SIZE: usize = 1_048_576;
```

In the function that parses documents (likely `AnalysisContext::new()` or equivalent),
add a size check BEFORE tree-sitter parsing:
```rust
if text.len() > MAX_YAML_SIZE {
    // Return empty analysis context with a single "file too large" diagnostic
    // instead of trying to parse
}
```

### Commit 3: Wire into LSP Server

**`nika-lsp/src/server.rs`** — in `did_open` and `did_change`:

```rust
// After updating document state, compute diagnostics
let diagnostics = nika_lsp_core::handlers::diagnostics::compute_diagnostics(&text);

// Convert NikaDiagnostic → lsp_types::Diagnostic
let lsp_diagnostics: Vec<Diagnostic> = diagnostics.iter().map(|d| {
    let range = byte_offset_to_range(&text, d.start, d.end);
    Diagnostic {
        range,
        severity: Some(match d.severity {
            Severity::Error => DiagnosticSeverity::ERROR,
            Severity::Warning => DiagnosticSeverity::WARNING,
            Severity::Information => DiagnosticSeverity::INFORMATION,
            Severity::Hint => DiagnosticSeverity::HINT,
        }),
        message: d.message.clone(),
        code: d.code.as_ref().map(|c| NumberOrString::String(c.clone())),
        source: Some("nika".to_string()),
        ..Default::default()
    }
}).collect();

self.client.publish_diagnostics(uri, lsp_diagnostics, None).await;
```

**Helper**: `byte_offset_to_range()` — convert byte offsets to LSP Position (line, character).
This is standard: iterate the text counting newlines.

**Commit**:

publishDiagnostics fires on document open/change. Error squiggles
now visible in VS Code and JetBrains for .nika.yaml files.

## Phase 3: Structured Output Polish (3-4h, 2-3 commits)

### Context

Structured output has a 5-layer defense system. Three known issues from the S6 handoff:

### 3.1 — L1 Ghost Response

**Problem**: When L0 (tool injection) succeeds but the provider response contains
both a tool_call AND text content, the text content is silently dropped. In some
edge cases, the tool_call JSON is invalid but the text content has the correct answer.

**Research first**:
```bash
grep -rn "ghost\|L1\|tool_call.*text\|text.*tool_call" \
  tools/nika-engine/src/runtime/structured_output.rs \
  tools/nika-engine/src/runtime/executor/infer.rs \
  --include="*.rs" | head -20
```

**Fix**: When L0 tool_call extraction fails validation, check if the text content
parses as valid JSON matching the schema. If yes, use it (L1 fallback).

### 3.2 — Structured Output Cache

**Problem**: Identical structured output requests (same prompt + schema) should
be cacheable, but the cache key doesn't include the schema hash.

**Research first**:
```bash
grep -rn "cache\|CacheKey\|cache_key" \
  tools/nika-engine/src/runtime/structured_output.rs \
  tools/nika-engine/src/provider/ \
  --include="*.rs" | head -20
```

### 3.3 — Token Budget for Structured Retries

**Problem**: Structured output retries (L3/L4) don't deduct from the task's
token budget. A pathological case could retry indefinitely within budget.

**Research first**:
```bash
grep -rn "token_budget\|TokenReservation\|max_retries\|retry.*budget" \
  tools/nika-engine/src/runtime/structured_output.rs \
  --include="*.rs" | head -20
```
