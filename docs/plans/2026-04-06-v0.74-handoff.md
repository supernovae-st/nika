## P0 — BUG-10: `when:` skipped tasks block ALL downstream

### The 1-line fix

**File**: `tools/nika-engine/src/store/run_context.rs`, line 134-138

```rust
// CURRENT (buggy):
pub fn is_usable(&self) -> bool {
    matches!(self.status, TaskOutcome::Success | TaskOutcome::PartialSuccess { .. })
}

// FIX:
pub fn is_usable(&self) -> bool {
    matches!(
        self.status,
        TaskOutcome::Success | TaskOutcome::PartialSuccess { .. } | TaskOutcome::Skipped { .. }
    )
}
```

### Root cause chain

1. Task A has `when: "{{expr}}"` → evaluates to false
2. `runner.rs:1181-1215` stores `TaskResult::skipped(...)` with `output: Value::Null`
3. `TaskOutcome::Skipped { reason }` is stored (line 108-117 of run_context.rs)
4. Task B depends on A (via `depends_on:` or `with:` implicit dep)
5. `runner.rs:612-629` calls `is_completed_successfully(A)` → `is_usable()` → **returns false**
6. Task B marked `DependencyFailed` → NIKA-026 emitted
7. All downstream of B cascade-fail too

### What the docs promise (but don't deliver)

`docs/language-bible.md`, line 747:
> "Skipped tasks return null. Downstream tasks STILL RUN and receive null."

This is FALSE in v0.73. The fix makes it true.

### After the fix — binding behavior

Downstream `with:` bindings to skipped tasks will resolve to `null`:
- With `?? default`: returns the default ✓
- Without default: NIKA-072 "null value at path" ✗

Users MUST use `?? ""` or `| default("")` on bindings to skipped tasks:
```yaml
with:
  nllb: $nllb_anchor ?? ""         # safe — empty string if skipped
  glossary: $build_glossary ?? ""  # safe — empty string if skipped
```

### Regression test to add

```rust

    // Setup: 2-task DAG where A → B, A has when: false

    assert_eq!(ctx.is_completed_successfully("A"), Some(true));
    
    // Assert: downstream B should be in ready list

}

#[test]

    let mut ctx = RunContext::new();

```

### Impact on nk-jungo

Currently NLLB is removed from workflows because of this bug. When fixed:

```yaml
- id: nllb_anchor
  when: "{{with.needs_nllb}}"       # false for romance/germanic
  on_error: { ignore: true }         # graceful degradation if NLLB down
  retry: { max_attempts: 2, delay_ms: 1000 }
  fetch:
    url: "http://51.159.153.241:8790/translate/batch"
    ...

- id: translate
  with:
    nllb: $nllb_anchor ?? ""         # null → empty string if skipped
```

Also affects `build_glossary` — currently using a jq if/then/else workaround
instead of the cleaner `when:` gate.

## P1 — on_error: ship in v0.74 (already on HEAD)

### Status

Commit `35256dbbd` (Apr 5, 2026). 20 files, ~391 LOC. On HEAD, not tagged.

### The 3 strategies

```yaml
# 1. Swallow failure, output null, mark as Success
- id: nllb_anchor
  on_error: { ignore: true }

# 2. Retry with different provider (1 attempt, no further retries)
- id: translate
  on_error: { retry_with_provider: "anthropic" }

# 3. Execute a different task as recovery
- id: translate
  on_error: { fallback: translate_simple }
```

### Implementation details

- **Parser**: `on_error` in `KNOWN_TASK_KEYS` (parser.rs:1885), parsed as JSON (line 2114)
- **Analysis**: NIKA-290 validates fallback task IDs exist (analyze.rs:1410)
- **Runner**: Fires after ALL retry attempts exhausted (runner.rs:1502)
- **Depth limit = 1**: `is_fallback_execution` flag prevents infinite chains (runner.rs:1515)
- **Event**: `TaskFallbackTriggered` emitted (log.rs:1072)
- **Display**: Both live.rs and renderer.rs handle the event

### Known limitations

| Gap | Description |
|-----|-------------|
| Depth > 1 | Fallback task's own on_error is ignored |
| Per-iteration | for_each has fail_fast:false but no per-item on_error |
| retry_with_model | Can retry with provider, not model on same provider |
| Custom default | ignore always produces null, no custom fallback value |
| Conditional | Cannot select strategy based on error type/code |

## P2 — New: `| parse_yaml` transform

### Why

432 pre-built files exist in nk-jungo (216 locales × 2 files: translation-context.yaml + voice-translation.yaml). These were generated because `nika:read` returns raw text and there's no `| parse_yaml` to parse YAML at runtime.

### The ideal workflow (after this feature)

```yaml
# Zero pre-built files needed:
- id: read_full_locale
  invoke:
    tool: nika:read
    params:
      file_path: "./locales/{{inputs.locale | lower}}/locale-context.yaml"
      raw: true

- id: extract_context
  with:
    full: $read_full_locale | parse_yaml
  invoke:
    tool: nika:jq
    params:
      data: "{{with.full | to_json}}"
      expr: "{locale, locale_differentiation, communication, spelling, formatting}"
```

### Implementation

File: `tools/nika-core/src/binding/transform.rs`

1. Add to `TransformOp` enum:
```rust
ParseYaml,
```

2. Add to `KNOWN_TRANSFORM_NAMES`:
```rust
"parse_yaml" => TransformOp::ParseYaml,
```

3. Add apply logic (after `ParseJson` block):
```rust
TransformOp::ParseYaml => {
    let s = as_string(value, "parse_yaml")?;
    let cleaned = s
        .trim_start_matches("```yaml")
        .trim_start_matches("```yml")
        .trim_start_matches("```")
        .trim_end_matches("```")
        .trim();
    crate::util::parse_yaml_budgeted(cleaned)
        .map_err(|e| type_mismatch("parse_yaml", &format!("valid YAML: {e}"), value))
}
```

`serde_saphyr` (aliased from `serde_yaml`) is already a dependency. `parse_yaml_budgeted` already exists in `nika-engine/src/lib.rs:29` with security limits.

4. Add test:
```rust
#[test]
fn test_parse_yaml() {
    let yaml = Value::String("name: hello\ncount: 42\n".to_string());
    let result = apply_transform(&yaml, &TransformOp::ParseYaml).unwrap();
    assert_eq!(result["name"], "hello");
    assert_eq!(result["count"], 42);
}
```

## P2 — New: `nika:json_diff` tool

Compare source and translated JSON for translation QA.

### Params
```yaml
invoke:
  tool: nika:json_diff
  params:
    source: "{{inputs.content}}"
    target: "{{with.translation | to_json}}"
```

### Returns
```json
{
  "identical_values": ["nav.settings"],
  "modified_values": ["hero_title", "cta"],
  "added_keys": [],
  "removed_keys": [],
  "length_ratios": {
    "hero_title": { "source_len": 28, "target_len": 36, "ratio": 1.28 },
    "cta": { "source_len": 30, "target_len": 52, "ratio": 1.73 }
  },
  "suspicious": ["nav.settings"]
}
```

`identical_values` = untranslated strings (suspicious).
`length_ratios` > 3.0 = likely error (too verbose).
`length_ratios` < 0.3 = likely truncation.

File: `tools/nika-engine/src/runtime/builtin/json_diff.rs` (new file)
Register in: `tools/nika-core/src/catalogs/builtins.rs`

## Hidden features to document / use in nk-jungo

### POST /v1/batch/run (exists, undocumented for Nicolas)

```bash
curl -X POST http://51.159.87.214:3000/v1/batch/run \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"workflows": [
    {"workflow": "jungo/translate-text.nika.yaml", "inputs": {"text": "Hello", "locale": "fr-FR"}},
    {"workflow": "jungo/translate-text.nika.yaml", "inputs": {"text": "Hello", "locale": "ja-JP"}},
    ...
  ]}'
```

Max 50 per batch. Configured via `NIKA_SERVE_BATCH_MAX`.

### Webhook on job completion

```bash
# Set on VPS:
export NIKA_WEBHOOK_URL=https://nicolas-backend.example.com/webhooks/nika
export NIKA_WEBHOOK_SECRET=my-secret

# Nika sends HMAC-signed POST on completed/failed
# SSRF-protected (blocks private IPs, metadata endpoints)
```

File: `tools/nika-serve/src/webhook.rs`

### Per-task timeout

```yaml
- id: nllb_anchor
  fetch:
    url: ...
    timeout: 15  # seconds, not ms
```

Already supported on all verbs (exec, fetch, invoke). Default workflow timeout: 3600s.

### base_url: per-task (route to vLLM/Qwen)

```yaml
- id: translate_cjk
  infer:
    base_url: "http://51.159.153.241:8000/v1"  # H100 Qwen
    prompt: ...
```

Creates transient OpenAI-compatible provider. Uses `OPENAI_API_KEY` or `"no-key"`.

### repair_model on structured output

```yaml
structured:
  from_example: ...
  repair_model: "gpt-4.1-mini"  # 10x cheaper for JSON repair
```

### Prompt caching (Anthropic 90% discount)

Skills = system prompt = cached across requests. When using `routing: { fallback: [openai, anthropic] }`, Anthropic calls pay only 10% for cached input tokens ($0.08/M vs $0.80/M).
