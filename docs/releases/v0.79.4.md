> *A codebase that asks you to write the same match statement twice in different files is a codebase that drifts.*
>
> *This release is invisible to workflow authors and essential for contributors. It introduces `nika-macros`, a new layer-zero proc-macro crate that eliminates three classes of hand-written boilerplate: error-code mappings, event-task-id mappings, and builtin-tool registrations.*

---

## TL;DR

1. **New crate: `nika-macros`** at architectural layer L0. Pure compile-time codegen, zero runtime dependencies, zero I/O.
2. **`#[derive(NikaErrorCode)]`** — generates `fn code(&self) -> &'static str` from `#[nika_code("NIKA-XXX")]` attribute metadata. Replaces a ~600-line hand-written match statement in `NikaError::code`.
3. **`#[derive(EventTaskId)]`** — generates `fn task_id(&self) -> Option<&str>` for `EventKind` enum. Replaces ~110 LOC of hand-written dispatch.
4. **`#[builtin_tool]`** — attribute macro on `impl BuiltinTool for FooTool` blocks. Enforces the sealed-trait pattern and auto-registers tools in `KNOWN_BUILTIN_TOOLS`.
5. **Zero breaking changes.** If you write workflows, upgrade is a no-op. If you embed `nika-core`: same API, same types.

---

## Why codegen, why now

The engine has three enum dispatch tables that were all hand-maintained:

- `NikaError::code()` — 600+ lines matching `NikaError::FooBarError { .. } => "NIKA-XYZ"` across every variant. Growing every session.
- `EventKind::task_id()` — 110+ lines matching events that carry a task ID vs those that don't.
- `KNOWN_BUILTIN_TOOLS` — a hand-maintained `[&str]` array in `nika-core::catalogs::builtins`.

Every new error variant required editing three files in three crates: define the variant, add the code mapping, add to the error-codes catalog. Drift risk was inevitable and actually happened — `NIKA-310..314` course errors had catalog entries for months while the variants were being built.

This release replaces all three tables with proc-macro attribute metadata. The mapping moves from "two hand-edited files" to "one source of truth on the enum itself". Drift becomes compile-time impossible.

## The three macros

### `#[derive(NikaErrorCode)]`

Before v0.79.4 (hand-written, in `nika-engine/src/error.rs`):

```rust
impl NikaError {
    pub fn code(&self) -> &'static str {
        match self {
            NikaError::WorkflowParseError { .. } => "NIKA-000",
            NikaError::WorkflowMissingField { .. } => "NIKA-001",
            // ... 250+ arms ...
            NikaError::ShieldCanaryLeaked { .. } => "NIKA-382",
            NikaError::ShieldRunDepthExceeded { .. } => "NIKA-386",
            // ... more arms ...
        }
    }
}
```

After v0.79.4:

```rust
#[derive(NikaErrorCode, ...)]
pub enum NikaError {
    #[nika_code("NIKA-000")]
    WorkflowParseError { .. },

    #[nika_code("NIKA-001")]
    WorkflowMissingField { .. },

    // ...
}
```

The derive generates exactly the same `fn code(&self) -> &'static str` at compile time. Display output is byte-identical. Nine golden tests lock the output down — any regression fails CI.

### `#[derive(EventTaskId)]`

Generates `fn task_id(&self) -> Option<&str>` for `EventKind`. Variants that carry a task context get the attribute:

```rust
#[derive(EventTaskId, ...)]
pub enum EventKind {
    #[event_task_id("task_id")]
    TaskStarted { task_id: String, /* ... */ },

    #[event_task_id("task_id")]
    ProviderResponded { task_id: String, /* ... */ },

    // Variants without the attribute return None
    WorkflowStarted { /* ... */ },

    // Custom field name supported
    #[event_task_id("parent_task_id")]
    SubtaskSpawned { parent_task_id: String, /* ... */ },
}
```

Previously 110 LOC of match arms. Now 1-line attributes on the 40+ variants that carry task context.

### `#[builtin_tool]`

Attribute macro on builtin tool impls. It:

1. Synthesizes the `name()` method from the struct identifier (`SleepTool` → `"nika:sleep"`)
2. Registers the tool at compile time in the `KNOWN_BUILTIN_TOOLS` catalog
3. Enforces the sealed-trait pattern (prevents out-of-crate implementations)
4. Asserts the trait bound `Send + Sync + 'static`

Before:

```rust
impl BuiltinTool for SleepTool {
    fn name(&self) -> &'static str { "nika:sleep" }
    // ... 60+ LOC of trait impl ...
}

// Then in nika-core/src/catalogs/builtins.rs, hand-add:
"nika:sleep",
```

After:

```rust
#[builtin_tool("nika:sleep")]
impl BuiltinTool for SleepTool {
    // ... 60 LOC — name() auto-generated ...
}
```

The catalog is generated at link time by collecting every `#[builtin_tool]` site. Adding a tool is a one-file change; the catalog stays in sync automatically.

## Where `nika-macros` sits

```
L0  KERNEL-ADJACENT (pure, compile-time)
    nika-core                 AST, types, catalogs, trust
    nika-event                EventLog, TraceWriter
  ▶ nika-macros               proc-macros (new in v0.79.4)
```

`nika-macros` has ONE dep: `syn` + `quote` + `proc-macro2` (the standard proc-macro trio) + `darling` for attribute parsing. Zero runtime deps. The output is pure Rust code the compiler expands at build time; nothing ships in the binary.

Embedders of `nika-core` don't need `nika-macros` directly — `nika-core` re-exports the derive macros via `pub use nika_macros::{NikaErrorCode, EventTaskId, builtin_tool};`. If you define your own `NikaError`-like enum, you can use the derive; if not, you don't care.

## Install / Upgrade

Drop-in upgrade from any v0.79.x.

```bash
brew update && brew upgrade nika
# or
cargo install nika --locked
# or
docker pull ghcr.io/supernovae-st/nika:0.79.4
```

**Embedders:** `nika-macros` is published to crates.io. If you're consuming `nika-core`, no action needed — the derives are re-exported. If you want the macros independently: `cargo add nika-macros`.
