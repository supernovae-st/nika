## ⚠️ Security advisory — upgrade strongly recommended

This release fixes **two** high-severity vulnerabilities:

- **NIKA-SA-2026-001** — command blocklist bypass via `\r` / `\x0B` / `\x0C` control characters. **Severity: HIGH** if you run untrusted workflow files with `exec: { shell: true }`.
- **NIKA-SA-2026-002** — stack-overflow DoS via pathologically nested JSON in secret-redaction. **Severity: MEDIUM** — affects the daemon process that writes NDJSON traces.

Both are fixed in this release. Upgrade immediately if you run Nika in a multi-tenant or untrusted-input context.

## TL;DR

1. **New crate: `nika-security`** at layer L1. Extracted from `nika-engine` (`−3,013 LOC`). Command blocklist, path validation, secret redaction, environment-variable safety — now independently testable and reusable.
2. **Six new provider redact patterns:** Replicate, Mistral, fal.ai, Cohere, ElevenLabs, Together. API keys from these providers are now redacted from traces, errors, and structured logs.
3. **CVE-class blocklist bypass fix** (`\r`/`\x0B`/`\x0C`) — `7192e728b`. The ASCII fast-path in `contains_unquoted` treated only ASCII space as a separator; control characters slipped through.
4. **DoS fix: `MAX_REDACT_DEPTH=128`** — `a949149a8`. Pathological JSON nesting no longer stack-overflows the redactor.
5. **`NIKA-999 Internal` error variant** — new catch-all with `{ context, detail }` fields. Five wildcard match arms across the engine now surface as `NIKA-999` instead of misleading domain-specific codes.
6. **`lib.rs` split into 6 modules** — `blocklist`, `command`, `injection`, `normalize`, `env`, `tests`. No file exceeds the 1,500 LOC rule.
7. **Four perf quality wins** — let-else env-var validation, `Cow<str>` normalization return, ASCII fast-path, inline format args.

## `nika-security` — what moved and why

The extraction is a direct response to three findings from the post-S17 architecture review:

- Security code was scattered across `runtime/security.rs` (2,463 LOC, command blocklist) and `io/security.rs` (549 LOC, artifact path validation). No coherent API surface.
- `redact_secrets` (a static regex bank) lived in `nika-engine/src/util/redact.rs` with only eight provider patterns, missing six production providers that Nika actively supports.
- Display-parity golden tests for error codes were absent; a wildcard match arm in `From<SecurityError> for NikaError` could silently change the error code of a security violation.

### What moved

| Source (before) | Destination (after) |
|---|---|
| `nika-engine/src/runtime/security.rs` (2,463 LOC) | `nika-security/src/command.rs` + `blocklist.rs` + `injection.rs` |
| `nika-engine/src/io/security.rs` (549 LOC) | `nika-security/src/path.rs` |
| `nika-engine/src/util/redact.rs` | `nika-core/src/util/redact.rs` (moved, expanded to 14 providers) |

### New public surface

```rust
// nika-security/src/lib.rs
pub enum SecurityError {
    BlockedCommand { reason: String, command: String },
    BlockedEnvVar { name: String, reason: String },
    ArtifactPath { path: PathBuf, reason: String },
    InvalidInjectionPattern { pattern: String },
    ShellEscapeRequired { template: String },
    // ... #[non_exhaustive] — more variants may be added
}

// nika-engine/src/error.rs
impl From<SecurityError> for NikaError {
    fn from(err: SecurityError) -> Self {
        match err {
            SecurityError::BlockedCommand { reason, command } =>
                NikaError::BlockedCommand { reason, command },
            SecurityError::ArtifactPath { path, reason } =>
                NikaError::ArtifactPathError { path: path.display().to_string(), reason },
            // ...
            other => NikaError::Internal {
                context: "security".into(),
                detail: format!("unmapped SecurityError variant: {other:?}"),
            },
        }
    }
}
```

`#[non_exhaustive]` + wildcard arm = invariant #25. Any future variant stays triageable from logs.

### Embedders

If you import from `nika-engine` today, you don't need to change anything — the engine re-exports relevant types from `nika-security`. If you want to consume the security crate directly:

```toml
[dependencies]
nika-security = "0.79.6"
```

Zero runtime deps, L1-layer (one dep on `nika-core`, one on `nika-event`). Suitable for reuse in any Rust project that needs Nika-grade command blocklist + path validation.

## ⚠️ NIKA-SA-2026-001 — Command blocklist bypass

**Severity: HIGH** (when `shell: true` is used on untrusted workflow input)

**Affected versions:** all releases through v0.79.5.

**Fix:** v0.79.6 (`7192e728b`).

### Description

`nika-security::blocklist::contains_unquoted` (formerly `runtime::security::contains_unquoted`) had an ASCII fast-path optimization that accepted command strings without going through full normalization if no ASCII space characters were detected. The blocklist was then matched against the *normalized* form.

An attacker-controlled command containing `\r` (0x0D carriage return), `\x0B` (vertical tab), or `\x0C` (form feed) as token separators — all of which the tokenizer in normalization treats as whitespace — passed the ASCII fast-path (no ASCII space present) without normalization. The unnormalized form was checked against a blocklist that expected normalized input. Patterns like `"rm -rf /"` did not match.

**Example exploit:**

```yaml
# workflow.yaml (untrusted input)
tasks:
  - id: exfil
    exec:
      command: "rm\x0D-rf\x0D/tmp/secret-artifacts"
      shell: true
```

Before v0.79.6: the command passed the blocklist check and executed.
After v0.79.6: the command is rejected with `NIKA-053 BlockedCommand`.

### Fix

The ASCII fast-path now treats `\r`, `\x0B`, and `\x0C` as separators equivalent to ASCII space. Added a fuzz test with 64 control-character permutations that must all be rejected.

### Mitigation for earlier versions

If you cannot upgrade immediately, disable `shell: true` for any workflow that processes untrusted input. Set `[policy.security] allow_shell_mode = false` in `nika.toml`.

### Credit

Found during the S19 post-extraction security audit by the internal 4-agent review swarm (the "scanner effect" — extractions reveal bugs that coupling hid).

## ⚠️ NIKA-SA-2026-002 — Stack overflow DoS in secret redaction

**Severity: MEDIUM**

**Affected versions:** all releases that emit NDJSON traces with MCP tool-result redaction (v0.77.0+).

**Fix:** v0.79.6 (`a949149a8`).

### Description

`redact_value` (the recursive JSON redactor) had no depth limit. An MCP server response (trusted input from a misconfigured server, or untrusted input from a malicious one) with 10,000+ levels of nesting caused the redactor to recurse past the default Rust stack size and crash the daemon.

Trace emission happens on every `invoke:` call that returns MCP results. The daemon crash dropped all in-flight trace writes.

### Fix

```rust
// nika-core/src/util/redact.rs
pub const MAX_REDACT_DEPTH: usize = 128;

pub fn redact_value(value: &Value) -> Value {
    redact_value_inner(value, 0)
}

fn redact_value_inner(value: &Value, depth: usize) -> Value {
    if depth >= MAX_REDACT_DEPTH {
        return Value::String("[REDACTED: depth limit]".into());
    }
    // ...
}
```

128 levels is generous for any real JSON document (most are <10). Fuzz-tested with 1,000-level fixtures; redactor returns gracefully.

## Six new provider redact patterns

Before v0.79.6, the redactor knew about these providers' API key formats:

```
Anthropic, OpenAI, Groq, DeepSeek, Gemini, xAI, GitHub, Slack
```

Missing patterns for six providers Nika supports:

| Provider | Key format | Detection |
|---|---|---|
| **Replicate** | `r8_...` | Prefix-anchored regex |
| **Mistral** | Mistral-issued opaque keys | Prefix + format hints |
| **fal.ai** | `fal_key:...` | Prefix-anchored |
| **Cohere** | 40-char alphanumeric | Context-anchored (`cohere-api-key:` prefix in logs) with no-false-positive guards |
| **ElevenLabs** | 32-hex | Context-anchored |
| **Together** | Issued opaque keys | Context-anchored |

**Why some are context-anchored.** A 40-character alphanumeric string matches many non-secret things (UUIDs-without-dashes, git SHAs, hashes). Rather than a naive prefix regex, the redactor only triggers when the surrounding context (a JSON key name, HTTP header name, or environment variable reference) matches a known "this is a secret" marker for that provider. False-positive rate: ~0 in the test corpus.

Cohere in particular was redaction-untrusted pre-v0.79.6 (40-char keys looked identical to many other tokens). The new context-anchored match captures Cohere keys in traces but ignores similar-looking random strings.

### Testing

Each new pattern has:
- Positive test: real (rotated) key is redacted
- Negative test: similar-looking non-secret is NOT redacted
- Runtime-constructed test fixture per GitHub push protection (no hardcoded keys even in tests)

## `NIKA-999 Internal` — new catch-all error

Before v0.79.6, when a verb crate returned an error variant the engine didn't know how to map, the wildcard match arm produced a misleading domain-specific error:

```rust
// Before
impl From<VerbInvokeError> for NikaError {
    fn from(err: VerbInvokeError) -> Self {
        match err {
            VerbInvokeError::Mcp(inner) => inner.into(),
            VerbInvokeError::Builtin(inner) => inner.into(),
            other => NikaError::McpProtocolError {                // ← misleading
                reason: format!("unknown invoke error: {other:?}"),
            },
        }
    }
}
```

Any future variant would surface as `NIKA-100 McpProtocolError` — confusing for users when the real cause was something else entirely.

After v0.79.6:

```rust
// After
impl From<VerbInvokeError> for NikaError {
    fn from(err: VerbInvokeError) -> Self {
        match err {
            VerbInvokeError::Mcp(inner) => inner.into(),
            VerbInvokeError::Builtin(inner) => inner.into(),
            other => NikaError::Internal {
                context: "verb-invoke".into(),
                detail: format!("unmapped VerbInvokeError variant: {other:?}"),
            },
        }
    }
}
```

Five wildcard arms updated (`SecurityError`, `VerbExecError`, `VerbInvokeError` ×2, `VerbInferError`). Three new Display-parity golden tests lock the format of `NIKA-053`, `NIKA-280`, `NIKA-999`.

`NIKA-999` is reserved for "this shouldn't happen" paths. If you see one in production, please file an issue — it means a verb crate grew a variant the engine didn't learn how to map.

## `lib.rs` split (invariant: no file > 1,500 LOC)

`nika-security::lib.rs` was 2,481 LOC after the extraction — violating the project invariant. Split into:

```
nika-security/src/
├── lib.rs           public re-exports + SecurityError + ~150 LOC
├── blocklist.rs     100+ dangerous command patterns, matcher
├── command.rs       tokenizer, normalization
├── injection.rs     prompt-injection pattern detection
├── normalize.rs     whitespace + case + path normalization
├── env.rs           environment-variable safety
└── tests.rs         unit tests
```

Largest module after the split: `tests.rs` at ~770 LOC. Production modules all well under 1,500.

`contains_unquoted` was rewritten during the split as a zero-alloc byte-slice matcher (was `String::contains` with intermediate allocations). Not strictly a perf fix — the old version was fast enough — but the byte-slice form enabled the fuzz corpus test that caught the `\r` bypass.

## Perf quality wins

Four micro-optimizations landed alongside the split:

1. **`is_valid_env_var_name` let-else + byte-level** — 4× faster. Used on every env var lookup in every task execution.
2. **`normalize_first_token_basename`** returns `Cow<str>` — zero alloc for non-trimmed paths (the common case).
3. **`normalize_for_blocklist` ASCII fast-path** — avoids `to_ascii_lowercase` alloc when input is already lowercase.
4. **Inline format args** across the module — `format!("{}:", name)` → `format!("{name}:")`. Several hundred sites. No functional change; reads better.

Combined: microseconds per command check. Matters at scale (multi-tenant Nika daemons processing thousands of workflow tasks/second).
