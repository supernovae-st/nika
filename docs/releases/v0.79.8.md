## TL;DR

1. **`binding/resolve.rs` — the heart of Nika template resolution — moves from `nika-engine` to `nika-core`.** The engine went from owning a 3,948-LOC resolver to wrapping a 600-LOC shim around a 1,200-LOC pure resolver. No user-visible change.
2. **New kernel trait: `BindingStore`** with nine methods. `resolve_env`, `get_binding`, `resolve_task_output`, etc. The resolver is now generic over `&dyn BindingStore`, so it compiles independently of any concrete storage.
3. **137 resolver tests migrated to `nika-core`.** The test infrastructure, which lived in `nika-kernel-mock`, moved along — `MockBindingStore` now lives in `nika-core` behind a `mock-bindings` feature flag.
4. **Four earlier binding modules moved in S21**: `binding/transform/` (65 pipe transforms), `binding/jsonpath.rs`, `binding/template/`, `binding/event.rs`. All pure. All now at L0.
5. **Zero breaking changes.** Workflow YAML, template syntax (`{{with.alias | pipe}}`), transform behavior — all identical.

---

## Why this migration matters

Template resolution is where `{{with.foo}}` becomes a concrete value. Every `infer:`, `fetch:`, `exec:`, `invoke:`, and `agent:` task invocation passes through it. It handles:

- Dotted path access (`$task.output.field`)
- Transform pipes (`{{with.data | upper | trim | json_flatten}}`)
- Default values (`$task ?? "fallback"`)
- Environment variable lookups (`$env.API_KEY`)
- Context file loading (`{{context.readme}}`)
- Loop variables inside `for_each`
- JSONPath queries
- Typed field coercion (65 templatable fields with automatic type conversion)

Before this release, all of that logic lived in `nika-engine`, coupled to `RunContext`, `Datastore`, and `EventLog`. To test a single template, you built a full engine execution environment.

After this release:

- Resolution is **pure** — given a `BindingStore` + a template string, the output is deterministic, fully testable with mocks, and has zero I/O.
- Embedders can use `nika-core::binding::resolve` to evaluate Nika templates outside the engine. Useful for LSP hover previews, static workflow analysis, `nika lint` rule evaluation.
- Engine refactors no longer risk breaking resolution — the engine's role shrinks to wiring its storage into the `BindingStore` trait.

## The four-session arc

### S21 — Four binding modules move (`60f586082`, `23abef211`, plus 5 cascade commits)

Before S21, `nika-engine/src/binding/` contained:

```
binding/
├── transform/          65 pipe transforms (upper, trim, jq, split, ...)
├── template/           template resolution — types, parser, context
├── resolve.rs          the big one — 3,948 LOC
├── jsonpath.rs         JSONPath query impl
├── event.rs            BindingEvent enum
├── entry.rs            BindingEntry type
├── store.rs            DatastoreBindingStore concrete impl
├── token_budget.rs     token-counting for `nika:token_count`
├── mock.rs             test-only
├── validate.rs         type coercion validation
└── types.rs, error.rs  small helpers
```

S21 moved four of them out:

| Module | Destination | LOC moved |
|---|---|---:|
| `binding/transform/` | `nika-core::binding::transform` | 1,304 |
| `binding/jsonpath.rs` | `nika-core::binding::jsonpath` | 218 |
| `binding/template/` | `nika-core::binding::template` | 872 |
| `binding/event.rs` | `nika-core::binding::event` | 112 |

The move required:
- **New trait `BindingStore` in `nika-kernel::binding`** — nine methods, object-safe, captures the read surface the resolver needs.
- **New error type `BindingResolveError` in `nika-core`** — the resolver no longer raises `NikaError` directly (it lives at L0, one layer below the error-code registry). Returns `BindingResolveError`; the engine shim converts to `NikaError`.
- **Orphan-rule workaround** — `BindingEvent` lives in `nika-core`; `EventKind` lives in `nika-event`; a direct `From<BindingEvent> for EventKind` impl was blocked by Rust's orphan rule. Instead, the conversion happens at the call site in engine — small loss of ergonomics, clean architectural layers.

S21 net: −1,906 engine LOC. Tests continue to pass 100%.

### S22 — `resolve.rs` becomes generic (5 commits)

The production `resolve.rs` was still in `nika-engine`, but S22 made it generic over the new `BindingStore` trait. Roughly:

```rust
// Before S22
pub fn resolve_template(template: &str, ctx: &RunContext) -> Result<Value, NikaError> {
    // ... reads ctx.bindings, ctx.datastore, ctx.env directly ...
}

// After S22
pub fn resolve_template<S: BindingStore + ?Sized>(
    template: &str,
    store: &S,
) -> Result<Value, BindingResolveError> {
    // ... reads store.get_binding(), store.resolve_task_output(), store.env_var() ...
}
```

Nine functions migrated: `resolve_template`, `resolve_path`, `resolve_pipe`, `resolve_default_value`, `resolve_action_templates`, `resolve_task_u32`, `resolve_task_bool`, `resolve_retry`, `resolve_required_bool`.

60 resolver tests migrated to use a `MockBindingStore` fixture. S22 was an investment session (D/A ≈ 0.6 because of the trait-signature rewrite surface) but it teed up S23.

### S23 — `resolve.rs` production moves (6 commits)

The production file itself moved. `tools/nika-engine/src/binding/resolve.rs` (3,948 LOC) became `tools/nika-core/src/binding/resolve.rs` (1,200 LOC) plus an engine shim `tools/nika-engine/src/binding/resolve_shim.rs` (600 LOC wiring).

**Why the shim stays.** The engine's `RunContext` provides concrete storage; it builds a `DatastoreBindingStore` adapter on the fly that implements the `BindingStore` trait. The shim also threads `EventKind::BindingResolved` events into `EventLog`, which the pure resolver knows nothing about.

The shim is pure wiring — no logic. When engine is refactored further in Act 2, the shim likely disappears entirely as `RunContext` gains a native `BindingStore` impl.

### S24 — `MockBindingStore` moves, circular dev-dep broken (7 commits)

`MockBindingStore` (488 LOC) lived in `nika-kernel-mock`. Once production resolve moved to `nika-core` (S23), `nika-core::tests` wanted to use `MockBindingStore` — but adding `nika-kernel-mock` as a dev-dep to `nika-core` would create a cycle (kernel-mock deps on core deps on core, transitively).

S24 broke the cycle by moving `MockBindingStore` to `nika-core` itself, gated behind a `mock-bindings` feature flag:

```toml
# nika-core/Cargo.toml
[features]
default = []
mock-bindings = []  # enables MockBindingStore for test fixtures
```

```rust
// nika-core/src/binding/mock.rs
#[cfg(feature = "mock-bindings")]
pub struct MockBindingStore { /* ... */ }

#[cfg(feature = "mock-bindings")]
impl BindingStore for MockBindingStore { /* ... */ }
```

137 resolver tests migrated from `nika-engine/tests` / `nika-kernel-mock/tests` to `nika-core/tests`. The `nika-kernel-mock` crate lost one of its five mock impls (it still has `MockProvider`, `MockHttpClient`, `MockShellExecutor`, `MockMcpPool`).

S24 also closed a **P0 visibility leak** from S23: nine resolver helper functions that were `pub fn` in `resolve.rs` should have been `pub(crate) fn` — they were internal helpers accidentally exposed. Demoted.

S24 also gated `insert_raw` / `mark_env_sourced` behind `#[cfg(test)] pub(crate)` — they were test-only APIs leaking into production API.

### `scripts/count-unwraps.py` refresh

The unwrap baseline (from v0.79.7) is **89**. S24 added awareness of feature-gated test modules to the counter, so `MockBindingStore` unwraps don't inflate the production count.

## The new `BindingStore` kernel trait

```rust
#[async_trait]
pub trait BindingStore: Send + Sync {
    fn get_binding(&self, alias: &str) -> Option<&Value>;
    fn resolve_task_output(&self, task_id: &str) -> Option<&Value>;
    fn resolve_path(&self, task_id: &str, path: &[String]) -> Option<Value>;
    fn env_var(&self, name: &str) -> Option<String>;
    fn context_file(&self, name: &str) -> Option<&str>;
    fn loop_var(&self, name: &str) -> Option<&Value>;
    fn resolve_env(&self, alias: &str) -> Option<String>;  // added S23
    fn is_task_skipped(&self, task_id: &str) -> bool;
    fn trust_level(&self, alias: &str) -> TrustLevel;
}
```

Nine methods. Object-safe. Async-safe. The engine's `RunContext` implements it in ~80 LOC via the `DatastoreBindingStore` adapter. `MockBindingStore` implements it in ~200 LOC with HashMap-backed storage.

Downstream consumers (LSP previews, static analysis, test fixtures) implement whichever methods they need — the rest can return `None` or the trait default.

## Migration (for embedders only)

If you imported resolver types directly:

```rust
// Before v0.79.8 (deprecated, works until v0.80.0)
use nika_engine::binding::resolve::{resolve_template, resolve_path};

// After v0.79.8 (recommended)
use nika_core::binding::resolve::{resolve_template, resolve_path};
```

If you want a `MockBindingStore` in your test fixtures:

```toml
[dev-dependencies]
nika-core = { version = "0.79.8", features = ["mock-bindings"] }
```

```rust
// In your test module
use nika_core::binding::mock::MockBindingStore;

#[test]
fn my_resolver_test() {
    let store = MockBindingStore::new()
        .with_binding("foo", json!({"bar": 42}))
        .with_env("API_KEY", "sk-...");

    let result = resolve_template("{{with.foo.bar}}", &store).unwrap();
    assert_eq!(result, json!(42));
}
```

If you want the BindingStore trait for a custom storage layer:

```rust
use nika_kernel::binding::BindingStore;

pub struct MyCustomStore { /* ... */ }

impl BindingStore for MyCustomStore {
    fn get_binding(&self, alias: &str) -> Option<&Value> { /* ... */ }
    // ... implement the 9 methods
}

// Now you can use nika_core::binding::resolve::* with your store
```
