> *AI is the new electricity. It should be accessible to everyone.*
>
> *But first, everything that isn't Nika has to go.*

This is the pre-launch reckoning. Not a roadmap. Not a promise. An audit.

Every crate, every command, every doc claim was put to a simple test: **does it exist in production, do users actually use it, and is every claim about it true?** This release contains the results — and the removals that followed.

**If you write `.nika.yaml` workflows, nothing breaks.** All five verbs (`infer`, `fetch`, `exec`, `invoke`, `agent`), all fourteen LLM providers, all sixty-three builtin tools, all sixty-five transforms, every workflow command (`run`, `check`, `test`, `eval`, `lint`, `graph`, `explain`) — unchanged. The binary is smaller. The claims are honest.

**If you used the TUI, the course, or the Zed/Neovim/Helix editor extensions,** this release removes them. Migration is below.

---

## The short version

1. **The TUI is gone.** `nika ui`, `nika chat`, `nika studio` — all removed. 88,985 lines of ratatui code and 40+ modules deleted in one commit. A clean TUI gets rebuilt post-launch against the diamond runtime.
2. **The course is gone.** `nika course next`, `nika init --course`, the 12-level / 44-exercise interactive tutorial — all removed. The [showcase library](../../examples/showcase/) (115 workflows) replaces structured learning for now.
3. **The Node and Python bindings are gone.** Never published. `nika-napi` and `nika-py` crates deleted. The forward path for programmatic access is [`nika-sdk`](../../tools/nika-sdk/).
4. **Three editor extensions are gone.** Zed, Neovim, Helix. None were on any marketplace. The VS Code extension is unaffected and remains the supported IDE surface.
5. **Nine phantom features are gone.** Error variants without constructors, struct fields never read, enum variants never matched. Defined but dead.
6. **The docs are now grep-verified.** "9 providers" → "14 LLM providers". "6-layer Shield" → "5-layer". "24 crates" → "32 crates". The ML injection detection claim is gone from SECURITY.md.
7. **CI workflows are cleaner.** TUI feature builds, Node SDK pipeline, and Python SDK pipeline — all removed from `.github/workflows/release.yml`.

**Net workspace change:** +218 insertions, −119,928 deletions = **−119,710 LOC**. One commit, `ceedcc727`, alone accounts for **88,985 LOC removed** — the TUI crate with its 40 modules, 11 integration tests, 1 example, and the ratatui/crossterm/tui-input workspace deps.

## Why this release exists

Nika has been in development for two years. The codebase accreted three kinds of weight:

- **Dependent scaffolding** — crates like `nika-tui` that shipped early to prove the concept and hardened around the pre-Constellation engine. They work, but they coupled to an architecture that has since changed four times. Every Constellation session that touched the engine had to thread cooperation with the TUI's state layer. Keeping the TUI frozen while the engine refactored wasn't an option — it would atrophy. Rebuilding it incrementally while the engine moved wasn't feasible either — too many concurrent breakages.
- **Speculative surface** — the Zed/Neovim/Helix editor scaffolds, the Node/Python FFI bindings, the 12-level course module. Each was written on the premise of "users might want this post-launch." None of them were validated. None shipped to a marketplace or registry. All of them took CI slots and mental overhead every release.
- **Phantom claims** — error codes with no constructors, SECURITY.md sections describing defenses that were never implemented, README tables with outdated counts. Docs that drifted from code and stayed drifted because nobody grep-verified.

A launch announcement post on Hacker News needs a repository that someone can `git clone`, `cargo build`, and read in an afternoon. Every one of those three weights made that harder. This release removes all three.

**The rule we used:** if it has zero production callers in the current code AND it isn't shipping in the launch binary, it's gone. No `#[deprecated]` shims, no feature flags, no migration helpers, no "coming soon" placeholders. Git history still has it. That's where dead code belongs.

## Migration guide

### If your workflow YAML uses `nika ui` / `nika chat` / `nika studio`

It doesn't. Those are CLI commands, not workflow constructs. If your shell scripts or CI pipelines call them:

```bash
# Replace any of these:
nika ui                        → nika run <workflow>.yaml
nika ui --view chat            → nika agent "your prompt"
nika chat -p claude            → nika infer "your prompt" -p anthropic
nika studio my-workflow.yaml   → nika graph my-workflow.yaml  # static DAG view
                                 + your editor (VS Code recommended)
```

### If you used the course

```bash
# Replace:
nika init --course          → nika init                 # project scaffolding still works
nika course next            → nika showcase list        # browse 115 curated workflows
nika course run <exercise>  → nika showcase extract <name>
                              nika run <extracted>.yaml
```

The [showcase README](../../examples/showcase/) documents the 115-workflow catalog. Each is self-contained, has inline comments, and can be extracted into the current dir.

### If you built against `nika-napi` (Node.js)

You didn't — it was never published. If you built against the internal crate directly via `path = "../nika/tools/nika-napi"`: delete the dependency and the import. The `nika-sdk` Rust crate provides the same API surface; Node FFI will return post-launch as a thin `nika-sdk` wrapper.

### If you built against `nika-py` (Python)

Same as above. `nika-py` was never on PyPI. Switch to invoking the `nika` CLI from your Python code via `subprocess`, or wait for the post-launch Python FFI built on `nika-sdk`.

### If you used the Zed/Neovim/Helix editor extensions

Your existing config keeps working with the unchanged LSP. For future updates, migrate to the VS Code extension, or fork the last-known-good editor config from git history (pre-`e6b19b4b7`).

### If you had `#[cfg(feature = "tui")]` or `nika-tui` in your `Cargo.toml`

Remove them. The feature and the crate are gone.

## The 3-Act strategy

For context on what happens next, this release opens Act 1 of a 3-Act pre-launch plan:

```
ACT 1   MONTH A — MEGA DELETION                    4 weeks, −100k+ LOC
        Week 1 ✓ done (this release)
        Week 2   engine fossil pass (+hygiene)     (~−250 LOC)
        Week 3   zombie backlog + Tier 2 audits    (~−5k LOC)
        Week 4   test theatre cleanup + memory

ACT 2   HYBRID EXTRACTION                          3–4 months
        engine → verb crates via kernel traits
        BlobStoreAdapter + HttpClientAdapter + McpPoolAdapter
        nika-runtime (re-extracted, this time real)
        nika-shield (unified L0-L5 crate)
        target: workspace 90–100k LOC, every crate ≤15k, every file ≤1500

ACT 3   REBUILD TUI                                6–8 weeks
        nika-tui-widgets (reusable ratatui)
        nika-tui-core (state, events)
        nika-tui-views (Studio, Command, Control)
        nika-tui-app (event loop)
        built against the stable diamond runtime — clean, not coupled
```

**No hard deadlines.** Quality > speed. Each gate (G1–G6) has exit criteria; Acts only advance when gates pass.

## Known gaps (from SECURITY.md)

Nika Shield is 5 wired layers + audit. This release does **not** change the honest gaps list from v0.79.4:

- **L1 Taint analysis** runs at `nika check` / `nika lint` time. **Not** enforced at `nika run` time. Remote workflows fetched via `nika run https://...` get zero runtime taint enforcement until Act 2 wires taint into the dispatcher.
- **MCP trusted-server policy** is not yet implemented. All MCP tool descriptions are wrapped with Spotlight regardless of server trust.
- **Artifact path allowlist + `..` rejection** — the L-SEC lint flags risky patterns, but the runtime enforcement is not yet implemented.
- **ML-based injection detection** — **not planned.** Removed from the stack in S20. The former `NIKA-383` / `NIKA-385` error codes are gone for good.
- **`InvocationSource::Remote` trust downgrade** — designed but not implemented. `nika run https://...` currently runs at full CLI trust. Use with caution.

The full threat model lives in [SECURITY.md](../../SECURITY.md).
