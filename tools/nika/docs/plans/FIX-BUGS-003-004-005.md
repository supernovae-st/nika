## Phase 1: BUG-003 - Implicit depends_on from use:

### Problem Statement

When a task has `use: { data: step1 }`, it should automatically depend on `step1`. Currently, users must add explicit `depends_on: [step1]` or the workflow fails with NIKA-081.

### Root Cause

`Dag::from_workflow()` in `src/dag/flow.rs` (lines 40-118) only builds edges from:
- `workflow.flows` section
- `task.flow` field (depends_on alias)

It ignores `task.use_wiring` completely.

### Fix Location

**File:** `src/dag/flow.rs`
**Insert after:** Line ~110 (after the task.flow loop)

### Implementation

```rust
// ═══════════════════════════════════════════════════════════════════════════════
// NEW: Build implicit edges from task-level use: wiring (v0.22.4)
// use: { data: step1 } creates implicit dependency: step1 -> this_task
// ═══════════════════════════════════════════════════════════════════════════════
for task in &workflow.tasks {
    if let Some(ref wiring) = task.use_wiring {
        let tgt_arc = task_set
            .get(task.id.as_str())
            .cloned()
            .unwrap_or_else(|| intern(&task.id));

        for (_alias, entry) in wiring {
            let dep_task_id = entry.task_id();

            // Skip self-references and non-task paths (context.*, inputs.*)
            if dep_task_id == task.id || !task_set.contains(dep_task_id) {
                continue;
            }

            let src_arc = task_set
                .get(dep_task_id)
                .cloned()
                .unwrap_or_else(|| intern(dep_task_id));

            // Add edge: dependency -> current_task (avoid duplicates)
            let adj_entry = adjacency.entry(Arc::clone(&src_arc)).or_default();
            if !adj_entry.contains(&tgt_arc) {
                adj_entry.push(Arc::clone(&tgt_arc));
            }

            let pred_entry = predecessors.entry(Arc::clone(&tgt_arc)).or_default();
            if !pred_entry.contains(&src_arc) {
                pred_entry.push(src_arc);
            }
        }
    }
}
```

## Phase 2: BUG-004 - Wrong Terminal Task Selection

### Problem Statement

When a workflow has multiple terminal nodes (tasks with no downstream dependencies), the final output picks arbitrarily from HashMap iteration order instead of the "deepest" task.

### Root Cause

`get_final_tasks()` in `flow.rs` returns unordered set.
`get_final_output()` in `runner.rs` iterates without sorting.

### Fix Location

**File:** `src/dag/flow.rs`
**Add:** `compute_depths()` and `get_deepest_final_task()` methods

**File:** `src/runtime/runner.rs`
**Modify:** `get_final_output()` to use deepest task

### Implementation (flow.rs)

```rust
impl Dag {
    /// Compute topological depth for each node (longest path from any root)
    fn compute_depths(&self) -> FxHashMap<Arc<str>, usize> {
        let mut depths: FxHashMap<Arc<str>, usize> = FxHashMap::default();

        // Initialize roots (no predecessors) with depth 0
        for task_id in &self.task_ids {
            if self.predecessors
                .get(task_id.as_ref())
                .map_or(true, |v| v.is_empty())
            {
                depths.insert(Arc::clone(task_id), 0);
            }
        }

        // Process remaining nodes in topological order
        let mut remaining: FxHashSet<Arc<str>> = self.task_ids
            .iter()
            .filter(|id| !depths.contains_key(id.as_ref()))
            .cloned()
            .collect();

        while !remaining.is_empty() {
            let mut progress = false;
            let mut to_remove = Vec::new();

            for task_id in &remaining {
                let preds = self.get_dependencies(task_id.as_ref());
                if preds.iter().all(|p| depths.contains_key(p.as_ref())) {
                    let max_pred_depth = preds
                        .iter()
                        .filter_map(|p| depths.get(p.as_ref()).copied())
                        .max()
                        .unwrap_or(0);
                    depths.insert(Arc::clone(task_id), max_pred_depth + 1);
                    to_remove.push(Arc::clone(task_id));
                    progress = true;
                }
            }

            for id in to_remove {
                remaining.remove(&id);
            }

            if !progress { break; }
        }

        depths
    }

    /// Get the deepest terminal task (for workflow output selection)
    /// Returns the terminal task with highest topological depth.
    /// On ties, picks the one that appears last in task definition order.
    pub fn get_deepest_final_task(&self) -> Option<Arc<str>> {
        let final_tasks = self.get_final_tasks();
        if final_tasks.len() <= 1 {
            return final_tasks.into_iter().next();
        }

        let depths = self.compute_depths();

        final_tasks
            .into_iter()
            .max_by(|a, b| {
                let depth_a = depths.get(a.as_ref()).copied().unwrap_or(0);
                let depth_b = depths.get(b.as_ref()).copied().unwrap_or(0);
                depth_a.cmp(&depth_b).then_with(|| {
                    // Tiebreaker: task definition order
                    let pos_a = self.task_ids.iter().position(|x| x == a).unwrap_or(0);
                    let pos_b = self.task_ids.iter().position(|x| x == b).unwrap_or(0);
                    pos_a.cmp(&pos_b)
                })
            })
    }
}
```

### Implementation (runner.rs)

```rust
/// Get the final output from the deepest terminal task
pub fn get_final_output(&self) -> Option<String> {
    // Use deepest terminal task (fixes BUG-004)
    let final_task = self.dag.get_deepest_final_task()?;

    self.datastore
        .get(final_task.as_ref())
        .and_then(|v| v.get("output"))
        .and_then(|v| v.as_str())
        .map(|s| s.to_string())
}
```
