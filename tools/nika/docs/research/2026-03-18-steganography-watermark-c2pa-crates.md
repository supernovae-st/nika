# Research Report: Rust Crates for Steganography, Invisible Watermarking, and C2PA Content Provenance

**Date**: 2026-03-18
**Scope**: crates.io survey + GitHub analysis
**Relevance**: Nika media pipeline -- AI-generated content provenance

---

## Executive Summary

The Rust ecosystem has a **production-grade C2PA implementation** maintained by Adobe/CAI, a
**neural watermarking crate** (also Adobe), and several steganography/blind-watermark libraries at
varying maturity levels. The `c2pa` crate is the standout: 8.6M+ downloads, 190 versions, actively
maintained (last release 2026-03-16), and it is THE industry standard SDK for content provenance.
For Nika, `c2pa` is the single most important crate in this entire research.

**Why this is HUGE for Nika:**
1. Every AI-generated image/video/audio from Nika workflows can carry a C2PA manifest
   declaring "this was generated by Nika workflow X at time T by model Y"
2. C2PA is backed by Adobe, Microsoft, Google, Intel, BBC, and every major content platform
3. The `rust_native_crypto` feature means no OpenSSL dependency -- perfect for Nika's
   cross-platform story
4. 20+ supported formats cover everything Nika's media pipeline produces
5. The crate has a `no_std`-compatible subset and WASM support path

**Integration sketch for Nika:**
```rust
// After media artifact generation:
// 1. Create a C2PA manifest with provenance metadata
// 2. Sign it with Nika's identity
// 3. Embed it in the output artifact
// Result: Every Nika output carries cryptographic proof of its AI origin
```

### 2. `trustmark` -- Adobe's Neural Watermarking (ICCV 2025)

| Field | Value |
|-------|-------|
| **Crate** | [`trustmark`](https://crates.io/crates/trustmark) |
| **Version** | 0.2.2 (2025-09-17) |
| **Downloads** | 8,931 total / 4,608 recent |
| **License** | MIT |
| **Repository** | [github.com/adobe/trustmark](https://github.com/adobe/trustmark) |
| **Authors** | Andrew Halle (Adobe) |
| **Published at** | ICCV 2025 (top-tier CV conference) |
| **Paper** | [TrustMark: Robust Watermarking and Watermark Removal for Arbitrary Resolution Images](https://arxiv.org/abs/2311.18297) |

**What it does:**
- Embeds invisible 100-bit payload into images using neural networks
- Survives JPEG compression, resizing, cropping, and other transforms
- Can REMOVE watermarks (for authorized use)
- Uses ONNX Runtime (`ort` crate) for inference -- no PyTorch needed
- Works with C2PA (designed to complement it)

**Dependencies:**
- `ort` (ONNX Runtime) -- for neural network inference
- `image` -- image processing
- `ndarray` -- matrix ops
- `fast_image_resize` -- efficient resizing with rayon parallelism

**Error correction modes:**
- BCH_SUPER, BCH_5, BCH_4, BCH_3 -- varying levels of error correction over 100-bit payload

**Why this matters for Nika:**
- Complements C2PA: C2PA metadata can be stripped from files, but TrustMark watermarks
  survive image manipulation
- Same organization (Adobe/CAI) as c2pa -- designed to work together
- Published at ICCV 2025 -- peer-reviewed, state-of-the-art
- 100-bit payload can encode workflow ID, timestamp hash, model identifier
- The ONNX dependency means ~35KB crate + downloaded model files at runtime

**Caveat:** Requires ONNX Runtime, which adds ~20MB to binary size. Best as an opt-in feature.

**What it does:**
- Blind watermarking (extract without original image)
- DWT + DCT + SVD frequency domain embedding
- Supports arbitrary binary data and strings
- Randomized block selection for security
- Uses `faer` crate for fast matrix ops + `rayon` for parallelism
- CLI tool included

**API example:**
```rust

```

**Assessment:** Very new (Dec 2025), low downloads, but clean API and MIT license. Good
lightweight alternative to TrustMark when ONNX Runtime is too heavy.

## Recommended Strategy for Nika

### Phase 1: C2PA Integration (HIGH PRIORITY)

```toml
[dependencies]
c2pa = { version = "0.78", features = ["rust_native_crypto"] }
```

Every media artifact produced by Nika should carry a C2PA manifest:
- **Action**: `c2pa.created` with `softwareAgent: "Nika/<version>"`
- **Assertion**: `c2pa.ai_generated` or `c2pa.ai_modified`
- **Provenance chain**: workflow ID, task ID, model used, timestamp
- **Signing**: Self-signed initially, then allow user-provided certificates

The `rust_native_crypto` feature avoids the OpenSSL dependency entirely.

### Phase 2: Invisible Watermarking (MEDIUM PRIORITY)

Two options depending on binary size tolerance:

**Option A -- TrustMark (best quality, heavy):**
```toml
[dependencies]
trustmark = { version = "0.2", optional = true }
```
Feature-gated behind `nika-watermark-neural`. Requires ONNX Runtime (~20MB).
Best for production environments where image quality and robustness matter.

**Option B -- blind_watermark (lightweight, good enough):**
```toml
[dependencies]
blind_watermark = { version = "0.1", optional = true }
```
Feature-gated behind `nika-watermark-classical`. Pure Rust, no ONNX.
Good for embedded/WASM scenarios. DWT/DCT/SVD is mathematically sound.

### Phase 3: Text Provenance (LOW PRIORITY, FUTURE)

```toml
[dependencies]
c2pa-text = { version = "1.0", optional = true }
```
Embed provenance in text outputs from `infer:` verb. Would make Nika the first
workflow engine to provide provenance for LLM-generated text.

## Key Insight: The C2PA + TrustMark Stack

Adobe designed these to work together as a layered provenance system:

```
Layer 3: C2PA Manifest (cryptographic, removable but verifiable)
Layer 2: TrustMark Watermark (invisible, survives image manipulation)
Layer 1: The actual content (image/video/audio)
```

- C2PA provides **legal/forensic provenance** -- who made this, when, how
- TrustMark provides **resilient identification** -- survives screenshots, crops, re-encoding
- Together they cover both the "metadata can be stripped" attack and the
  "image was re-uploaded without metadata" attack

This is exactly what Nika needs for responsible AI content generation.
